# Web Terminal (swiss-terminal)

> The web terminal plugin: one Terminal page hosting two kinds of real sessions — remote over the SSH connections tunnels has already configured, local via ConPTY/openpty; the session machine, one-shot tickets, backpressure, disconnect grace, and asciicast recording are all built in; the xterm.js panel and the WebSocket routes live in the swiss-panel static assets and the root crate's composition layer respectively.

## HTTP API and Routes

- Route table (src/plugins/terminal_api.rs:99-111): GET /api/terminal/targets; POST+GET /api/terminal/sessions; POST /api/terminal/sessions/{id}/ticket; GET /api/terminal/sessions/{id}/stream; POST /api/terminal/sessions/{id}/resize; DELETE /api/terminal/sessions/{id}.
- This crate (swiss-terminal) has no axum and no SSH; this is deliberate layering:
  - The HTTP/WS layer lives in the root composition crate: src/plugins/terminal_api.rs defines and mounts it, and src/server.rs:267 merges it into the extra tree — it must sit inside build_app's loopback guard and plugin boundary, because axum's layer() only covers routes that exist at mount time; merging afterwards would leave every /api/terminal route outside the only authentication (terminal_api.rs:1-9 module comment).
  - The session machine TerminalSessions lives in swiss-terminal and is exposed to the routes through TerminalState (a single-slot RwLock whose lifetime belongs to the plugin): installed at start, withdrawn at stop (terminal_api.rs:62-94; src/plugins/terminal.rs:181,189).
  - SSH lives in swiss-tunnels: the provider TunnelShells (crates/swiss-tunnels/src/tunnel/shell.rs:34-105) takes a connection reference via TunnelManager::open_shell and opens a russh channel (crates/swiss-tunnels/src/tunnel/manager.rs:514-535); the terminal crate never links an SSH client.
- Error mapping (terminal_api.rs:117-125): NoSession→404, Ticket→403, Refused→409, Shell→502; the message text is passed through verbatim (panel wording is not rewritten at the HTTP layer); a fallback 503 when the plugin is not running (terminal_api.rs:129-134).
- Geometry validation: cols/rows are first checked as u64 within 1..=1000 (MIN_PTY_AXIS/MAX_PTY_AXIS, crates/swiss-host/src/services/shell.rs:36-37) before narrowing to u16 — 70000 is rejected outright rather than clamped to the default (terminal_api.rs:149-173); PtySize::new is the single authority at the boundary (shell.rs:63-76).
- Ticket security (crates/swiss-terminal/src/terminal/tickets.rs): 24 hex/96 bits of CSPRNG (:29), TICKET_TTL 10 seconds (:24), single use — consumed on submission, burned even if judged to be for the wrong session, preventing grinding against the session list (:97-112, module comment :10-13); forgotten as soon as the session closes (:116-119); mint sweeps expired entries as a side effect (:84).
- The WS pump (terminal_api.rs:338-449): the read and write halves are independent — the read half owns the stream so keystrokes still get through while the write half is parked on a full queue (this is the backpressure design, not an optimization); the write half owns the attachment's frames/stalled receivers, detaches when it returns, and the grace clock starts; deliberately no extra outbound buffering, keeping the driver's CLIENT_QUEUE_FRAMES (16) and the stalled flag honest (module comment :20-36).

## Panel Pages and Interactions

- The page's three pieces: crates/swiss-panel/src/admin_assets/js/views/terminal.js (DOM/WS wiring), terminal-core.js (the pure-function half: URLs, reconnect stepping, control-frame text, geometry clamping, target rows, Windows key/mouse actions, font-size zoom — all unit-testable without a DOM), views/terminal-settings.js (the Local shell settings sheet). The panel's source of truth is crates/swiss-panel/panel/src (TypeScript; the admin_assets/js files are its committed ts-blank-space emit, ADR-024) — edit the .ts, never the emit.
- xterm.js vendored: js/vendor/xterm/xterm-5.5.0/ + addon-fit-0.10.0, addon-unicode11-0.8.0 (CJK/emoji column widths), addon-web-links-0.11.0, addon-webgl-0.18.0; UMD builds cannot be imported, so load-classic.js injects them via classic script tags and each package gets an index.js shim exporting named exports (docs/14 §8.1 T6); on WebGL context loss it disposes and falls back to DOM rendering (views/terminal.js:195-202). Fonts use the system monospace stack (views/terminal.js:31), no web fonts — the asset pipeline accepts only .html/.css/.js/.svg.
- Target selection: dropdown rows = the local row (when enabled, local · <label>, the label matched from local.shells candidates, terminal-core.js:110-125) + one row per tunnel connection, label · user@host[:port] (state); with no remote targets the reason names the tunnels plugin; when local is off and no targets are selectable, the empty-state row becomes the clickable Local shell is off — turn it on (views/terminal.js:524-540).
- Gear settings: the term-set button opens the Local shell sheet — the Enabled toggle (its rationale line taken directly from the schema description, one source, no fork), the Shell input + datalist candidates (any path can be typed manually); save = PUT /api/plugins/terminal/config, changing only the local key with everything else passed back unchanged, carrying a revision optimistic lock (losing loudly rather than silently overwriting); with live sessions, a confirm first states the restart cost (views/terminal-settings.js:20-77; terminal-core.js:141-155).
- Paste/copy follow Windows conventions (docs/15 P1): attachCustomKeyEventHandler + keyAction — Ctrl+V / Ctrl+Shift+V / Shift+Insert paste (return false; the browser's native paste lands in .xterm-helper-textarea; navigator.clipboard.readText is not used on the keyboard path); Ctrl+C with a selection = copy and clear the selection, no ^C sent; without a selection = SIGINT unchanged; Ctrl+Shift+C / Ctrl+Insert copy; right-click pastes or copies the selection, Shift+right-click keeps the browser menu as an escape hatch (terminal-core.js:167-197, 230-238; views/terminal.js:211-247). Multi-line paste goes through xterm's bracketed paste as-is, with no newline rewriting.
- Session tabs: one tab per session (the label uses the connection label, not the bare UUID); list polling fills in bytesOut/attached; closed sessions stay readable until the user dismisses them (the dismissed set shrinks with the inventory to prevent leaks); the reconnect loop treats the list as truth (sessionAlive), backing off from 500 ms doubling to a 5 s cap, re-minting the ticket each round (terminal-core.js:29-54; views/terminal.js:304-342).
- Font-size zoom: Ctrl+= / Ctrl+- / Ctrl+0 and Ctrl+mouse-wheel, 8..32px, remembered in localStorage; resize takes the dual channel — a resize frame when the socket is up, POST /resize when it is down (views/terminal.js:351-377).
- Lifecycle: mount/unmount releases the old mount's WS and xterm (otherwise the grace clock never starts and the WebGL context leaks); the epoch generation number invalidates all callbacks from the old mount (views/terminal.js:591-649).

## Configuration and Storage

- The config row plugins.terminal.config: strict parsing, errors name the key, never a silent fallback (crates/swiss-terminal/src/terminal/config.rs:69-137, tests :220-238):
  - local.enabled (default false — an upgrade that turns a loopback HTTP port into an arbitrary-code-execution entry deserves a manual opt-in, docs/14 §6.1), local.shell (empty = platform default);
  - allowedTargets: [] (empty = all tunnel connections; otherwise an exact-id whitelist);
  - maxSessions (default 4, 1..=64), maxSessionsPerTarget (default 2, must not exceed the total), idleTimeoutMinutes (default 30, 0 = never time out), graceSeconds (default 60), stallSeconds (default 30, all ≤ 86400), recording (default true).
  - The two caps govern remote only; local sessions are uncapped (user's decision on 2026-09-12: it is your own machine, and one local PTY costs only a thread stack); a local open neither checks nor consumes the remote budget (session.rs:607-649).
- Constants rather than config keys (memory-budget lines, docs/14 §7): catch-up buffer CATCHUP_BYTES = 64 KB (session.rs:58), recording cap RECORDING_MAX_BYTES = 8 MB (recording.rs:41), client queue 16 frames, command queue 32, STALL_NOTICE 1 s, CLOSE_FLUSH 250 ms (session.rs:63-76).
- config_schema mirrors the parser key for key, including default-value consistency tests (src/plugins/terminal.rs:51-116, 206-264); saves persist through the host's PUT /api/plugins/terminal/config, restart_on_config_change: true — saving restarts and closes all sessions with a reason.
- Recording files: ~/.swiss/terminal/<sessionId>.cast (the directory is created eagerly at plugin start — a read-only data directory errors on the inventory line rather than at first open, src/plugins/terminal.rs:169-174); directory 0700, files 0600; format = asciicast v2 header (version/width/height/timestamp/env.TERM=xterm-256color) + one line per chunk [elapsed,"o",text]; elapsed uses a monotonic clock (a mid-recording NTP jump cannot play backwards), timestamp uses the wall clock; UTF-8 reassembled across chunks (holding at most 3 bytes of an incomplete tail sequence), U+FFFD only for genuinely bad bytes (recording.rs:66-99, 181-222). *.cast is on AGENTS.md's Never commit list — shells echo what was typed, so a recording can contain a password.
- Credentials: the terminal's whole chain never sees a password or private key — what the provider hands over after opening the channel is a byte stream; if credentials ever appear in config, they must still be ${ENV_VAR} references only, never literals (docs/14 §6.3).
- Session ids: swiss_core::util::random_hex(16) (session.rs:401); local/remote uniformly counted as SessionLedger leases (local.rs:141; shell.rs:159-166).

## Lifecycle and Background Behavior

- One driver task per session, owning the PtySession exclusively; every outside operation (open/list/attach/resize/close) goes through the command channel — this is what makes "Ctrl-C still reachable during a flood" true: the driver's send loop keeps serving commands even while parked on a full output queue (session.rs:1-8, 780-947).
- Four clocks (session.rs:10-33): idle (no activity in either direction; output counts as activity — a compile printing for an hour is not idle), grace (starts when the last socket drops, output goes into the 64 KB catch-up buffer; a session opened but never attached sits on this clock from birth, incidentally reclaiming unclaimed POSTs), stall (attached but consistently receiving no bytes; a 1 s stalled warning first, then close), and the recorder's own 8 MB cap.
- Bytes are never dropped; the single exception is declared up front: a disconnected session's catch-up buffer drops from the front and owes a [gateway] notice line — no silent hole (session.rs:24-33, 692-735). The attached send path parks rather than drops: queue full → the driver stops reading → the provider stops reading the PTY/SSH channel → pressure propagates through the SSH window/pipe back to the printing program, exactly real tty behavior (docs/14 §6.8).
- The cursor mechanism for attachment fan-out: place_at + pending fields let a frame in flight be interrupted by a command and then resumed (rather than cancelled and losing bytes); an attachment joining mid-frame is topped up to the same frame when the cursor arrives, no more no less; an attachment dropping mid-frame removes only its own unserved slot (session.rs:744-759, 858-924).
- The close path finish(): first writes the reason into the terminal and the recording, then sends the final Exit/Error frame; hand_over gives each attachment a 250 ms deadline for delivery, then the session is deregistered from the table, tickets forgotten, a log written (session.rs:974-1002); dropping PtySession releases the provider lease, and for a local shell reaps the whole subtree as a bonus (ADR-008) (session.rs:991-994). CloseReason's seven variants each carry a user-facing sentence; all but natural shell exit deserve a word in the terminal (session.rs:159-207).
- Plugin stop: TerminalState::withdraw first unseats the machine (requests no longer reach a dying machine), then shutdown() — clearing the table directly drops the command senders, and the driver's select on Command(None) finishes with the Shutdown reason ("the plugin is stopping"; "closed on request" is left for the DELETE path) (session.rs:531-543, 826-828; src/plugins/terminal.rs:185-199).
- Concurrency correctness of the session caps: TableState.opening records in-flight opens (an SSH channel open is one round trip), so two concurrent opens cannot both see headroom; a Reservation's Drop releases the slot, so a half-failed open does not leak quota (session.rs:266-273, 615-690).
- Local PTY background: one spawn_blocking read thread per session (READ_CHUNK 32 KB) + a depth-1 channel — the depth is the backpressure chain (consumer parks → the read thread's blocking_send parks → the pipe goes unread → pressure reaches back to the program); teardown relies on the ownership chain: consumer drops → forwarder exits → channel closes → read thread returns → pump drops → the subtree dies; a quiet shell is woken from its blocking read by PtyHandle::kill at both async-half exits (local.rs:12-29, 145-151, 180-242; platform layer crates/swiss-core/src/platform/pty/mod.rs:11-30).
- Default shell resolution order (finalized in docs/15 §2.1): on Windows pwsh.exe (resolvable on PATH) → powershell.exe → COMSPEC → bare cmd.exe; on unix $SHELL → /bin/sh. The implementation is conpty.rs's pure-function family (default_shell :270, default_shell_in :279, find_on_path :297, find_on_path_with :303, shell_candidates :384, resolve_program :428); PATH/PATHEXT/COMSPEC/ProgramFiles are all parameters, and probing only asks metadata().is_file() without canonicalizing (WindowsApps execution aliases would dissolve into versioned package directories). LocalShells probes once at construction (= plugin start) and caches; it never touches the filesystem on each GET (local.rs:97-111).
- Subprocess environment (shell_command at local.rs:168-177): inherits the gateway environment, then layers on TERM=xterm-256color and COLORTERM=truecolor and removes NO_COLOR — the launcher's taste (the agent harness sets NO_COLOR=1) is not the tab's taste (the lesson of PSStyle being forced to PlainText on 19999 in practice); request-level shell override > configured local.shell > platform default (docs/14 §8.1 last item: without it the settings box is mere decoration).
- Remote provider lifecycle: the tunnels plugin registers TunnelShells as the last step of start (a failed start leaves no provider in the seat), and stop goes begin_withdraw → drain_sessions (3 s window DRAIN_TIMEOUT_MS; the window is for opens still landing — attached terminals will not hand themselves back) → close_all → clear the seat (src/builtin.rs:333-357; crates/swiss-host/src/services/shell.rs:54, 205-222).

## Relationship to the Host and Other Plugins

- Plugin descriptor: id terminal, kind terminal, version 0.1, one page (order: 70 — after jobs's 50 and before plugins's 1000, forming its own top-level group per docs/13), routes ["/api/terminal"] (route_owner prefix match), restart_on_config_change: true, requires: [] — deliberately not requires: ["ssh-shell"], otherwise local sessions would also park the whole plugin in waitingDependency over an unsatisfied dependency; the targets endpoint honestly reports remote availability (src/plugins/terminal.rs:42-141, tests :266-280; docs/14 §4).
- The shell capability slot ShellRegistry lives in RuntimeServices, constructed outside the plugins (the seat outlives plugin instances; a provider stopping and restarting gets the same seat): crates/swiss-host/src/services/shell.rs:462-571. Single-provider registration, duplicate registration names the incumbent, new sessions refused during withdraw, and last_provider_id retained when absent for honest naming. This is the second sample under ADR-010 (subsystem crates do not depend on each other) of "when the host contract is missing something, add to the contract" (the first is the docs/12 W3 connection catalog).
- PtySession is transport-neutral duplex (not a russh channel, not a ConPTY handle); remote and local return the same type, and the driver's single code path does not know which kind of shell it is pumping (shell.rs:250-420; the session machine imports only swiss_host::services::shell).
- SessionLedger leases are session-scoped, not request-scoped (compare the Data plugin's millisecond browser leases): drain waits asynchronously via watch rather than a condvar, and the window is deliberately short so as not to block the current_thread runtime (shell.rs:11-23, 141-248). The local LocalShells reuses the same ledger mechanism so the driver holds only one kind of session (local.rs:80-111).
- Reference counting goes through tunnels' existing release path: the ShellSessionGuard reference from TunnelManager::open_shell goes in with the pump task instead of being returned to the caller (only the pump knows when the session truly ends); while the terminal is open it shares the SSH client with existing tunnels, and closing the terminal does not take the tunnel down (manager.rs:504-535; docs/14 §8.1 T2 deviation record).
- Panel assets are edited directly in this repo (crates/swiss-panel/src/admin_assets/, ADR-016); the retired Node gateway had no terminal plugin — that page simply does not render and does not error.
- Registration sequence: src/server.rs:164 builds TerminalState first → :230 registers TerminalPlugin → :267 mounts the routes into the extra tree (inside the same guard as the tunnels/jobs/host services trees); the plugin boundary gives disabled /api/terminal/* a structured 503 (with an actionable re-enable hint).
- The descriptor's sidebar: false was corrected by live browser testing: the flag means "this page renders into the MCP sidebar layout", which only the mcps page should have; copying the docs/14 draft's true would have kept an MCP server list permanently beside the terminal (src/plugins/terminal.rs:126-130).

## Style and Design Observations

This plugin is a demonstration sample of the project-wide patterns:

- Plugin descriptor registration: every declaration to the host is data (descriptor, schema, routes, pages); the host never learns the string terminal; a new capability changes no host match arm (the direct embodiment of the docs/09 contract).
- Route-mounting discipline: routes are mounted into the extra tree in the composition crate and must sit inside the loopback guard and plugin boundary; subsystem crates stay zero-axum — the result is that swiss-terminal's full session test suite never touches a server, a socket, or real time (terminal_api.rs:4-9).
- A shared capability slot instead of a crate edge: when the terminal needs SSH it does not add a dependency edge but adds a capability contract to the host (ShellRegistry's shape copied from CatalogRegistry); the provider/consumer sides are mutually unaware (ADR-010; shell.rs:1-9).
- Honest absence: an absent remote in targets names the missing plugin (an empty list and "tunnels is disabled" are two different statements); error text is user-visible and passed through verbatim; refusals are specific — local not enabled, outside the whitelist, unknown target, and provider stopping are four different errors (session.rs:557-604).
- Memory discipline: budgets were written into the docs first (docs/14 §7, every line measured: remote session marginal 250.7 KB ≤ 256 KB, local ≈108 KB + thread stack, plugin loaded with zero sessions ≈0, catch-up buffer 64 KB × session count); buffer caps are constants, not config; the no-dropped-bytes principle holds along the whole chain with its single exception stated.
- Security boundary: local shell is off by default with a one-sentence rationale (the schema description and the panel hint share one source); one-shot tickets make "can open a terminal" explicit, isolating any future loosening of Origin checks on other endpoints; recording captures output only, avoiding sudo passwords; command blocklists are explicitly not done (command filtering on an interactive PTY is security theater — say no honestly, and put the limits on the remote host's real mechanisms).
- UI presentation: panel pure logic is separated from DOM wiring (terminal-core.js is unit-testable without a DOM); vendored dependencies are not minified, not one character changed, with version numbers in directory names; the settings sheet reuses the existing .sheet/.fld skeleton instead of writing another.
- Error handling and naming: every CloseReason variant carries a user sentence; the three ticket errors are individually distinguishable (clock skew and replay must be tellable apart in a bug report); ShellError's From is hand-written rather than #[from] (a consumer should not dictate the contract's shape back, session.rs:217-231).
- Testing culture: behavior changes came with tests first; tickets, caps, backpressure, UTF-8 across chunks, stop-at-cap recording, and schema/parser consistency all have targeted assertions; spec deviations are recorded item by item in docs/14 §8.1.

Inconsistent exceptions (all deliberate and on record):

- Local sessions are uncapped, deviating from the session-cap wording of docs/14 §6.6 — the user's decision on 2026-09-12, recorded as a deviation in docs/14 §8.1 and the session.rs:607-614 comment; maxSessions's schema description accordingly says Remote sessions only.
- The routes are not in this crate: seemingly at odds with the general principle that "capabilities live in subsystem crates", in fact a hard constraint of axum's layer-coverage semantics; the terminal_api.rs module header comment nails down the reason.
- POST /api/terminal/sessions/{id}/ticket is not in the original route table of docs/14 §8; it was added during implementation (the asymmetry of a 10 s ticket / 60 s grace), a documented deviation where the spec lagged the implementation.
- A recording failure does not block the session (a single warn; the list still reports the path), differing from the general "fail strictly" taste — an unwritable recording is not worth the user losing a terminal (session.rs:417-430).
- One blocking thread per local session defies the "don't spend memory for convenience" intuition, but it is the hard price of ConPTY's anonymous pipes being unpollable; the thread stack is still accounted in the docs/14 §7 budget for the user to weigh (local.rs:12-21; docs/14 §5).
