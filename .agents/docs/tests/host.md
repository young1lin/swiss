# Host and Core Mechanisms Integration Test Plan (functionality point → test matrix)

> Input: the Feature Overview table of [.agents/docs/host.md](../host.md) (host.md:9-38, 30 rows in total; not one row missing from this document's matrix); test baseline: root tests/ (app.rs 12 tests, adminapi.rs 71 tests, plugin_host.rs 28 tests, terminal_ws.rs 15 tests, http_adapter.rs 6 tests, memory.rs 1 test, env_precedence.rs 1 test, envelope_compat.rs 4 tests) + the inline #[cfg(test)] of swiss-host / swiss-core / swiss-panel / root src (about 380 inline tests in total for the host domain).
> Driving-discipline: everything drives `swiss::app::build_app` via `tower::ServiceExt::oneshot` (no real port; the only three exceptions follow the established pattern — a real rmcp client / WebSocket / adapter peer uses the ephemeral port 127.0.0.1:0); no bare sleep, polling at 20ms×cap; each test binary sets `MCP_GATEWAY_MASTER_KEY` once through an OnceLock (adminapi.rs's sandbox() / plugin_host.rs's test_master_key() / terminal_ws.rs's pin_home_and_key()); vault and traffic are process-global state, tests must hold `VAULT_LOCK`; this domain has no DB surface — any new case involving a DB must self-skip without credentials (both docs/08 iron rules observed in full).
