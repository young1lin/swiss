# Data Plugin: Database Browsing (swiss-data)

> Data is the panel's DBeaver-style database browser: it owns no connections itself; every `/api/db` request "rents" a connection from the MCP plugin through the host's connection catalog (ConnectionCatalog), providing table browsing, row paging, a single-statement SQL console (writes run), transactional edits, CSV import/export with streaming SQL dumps, and Redis key browsing with newest-first stream windows.

## HTTP API and Routes

**Mounting**: the router is built by `dbbrowser_router<S>(catalog: Arc<CatalogRegistry>, order: OrderSource, groups: GroupSource)` (crates/swiss-data/src/dbbrowser_api.rs:1171-1216) and merged into the main router in `build_app` (src/app.rs:555-560); the catalog, a sidebar-order source and a group-label source are injected via `Extension` layers rather than handler state, the catalog falling back to an empty registry when the composition root has not set one (all routes answer 503). `OrderSource` is a live closure (`Arc<dyn Fn() -> Vec<String>>`, dbbrowser_api.rs:61-77) read per request — the composition root supplies the sidebar's visual order (registry names ranked by the flat manual order, then sliced by group, src/app.rs:562-580), so a sidebar drag reorders the picker on the next poll without any remount. **Security boundary**: same as all of /api — loopback guard (`loopback_guard`, rejects non-loopback Host/Origin) + 2 MiB body cap (`BODY_LIMIT`) + plugin boundary (with the Data plugin disabled, its paths answer the host's 503) (app.rs:600-618;dbbrowser_api.rs:4-8;reply.rs:14). /api/db does no bearer auth (loopback is the gate, as the module comment states outright).

**Error contract**: `Fail{status,message}` → `admin_error`, i.e. the Node shape `{error:"…"}` (dbbrowser_api.rs:264;reply.rs:17-19). Three mappings plus one race: database/guard rejections → 400 (**driver message passed through verbatim**; module header comment: for someone staring at the grid, "Data too long for column 'x'" is exactly the useful answer); a buffered edit that loses a race against another writer → 409 carrying the moved columns and the row (docs/22 W4.2, Fail::conflict); Node-era 404 texts preserved verbatim (`unknown MCP: {name}`, `MCP 'x' (echo) has no database to browse`, now produced provider-side); catalog absent/stopping → 503 that **names** the missing party — "the mcp plugin provides database connections and is currently disabled" (dbbrowser_api.rs:166-190). body over 2 MiB → 413; invalid JSON body → 400 (reply.rs:43-66).

**Request-parameter fidelity**: query-string parameters are forwarded with Node's route-literal semantics — `q_non_empty` (missing and empty string both count as "not sent"), `q_raw` (numeric parameters as raw strings; the browser-side `js_number` does the blunt `Number()` coercion), `coerced_str` (`String(body[k] ?? "")`) (dbbrowser_api.rs:121-149).

## Panel Pages and Interactions

The panel assets are edited directly in this repo (crates/swiss-panel/panel/src, erased to the committed emit under src/admin_assets/js, ADR-024); the Data page consists of the data-*.ts family (17 modules — among them data-tabs.ts for the docs/42 object tab strip, data-tree.ts for the docs/43 keyspace tree, and data-stream.ts for the docs/45 stream view) plus db-state.ts; the view entry `views/data.ts` exposes `mount/refresh/hasPendingChanges/canLeave/unmount/countText` (navigation guard: leaving with uncommitted edits requires confirmation; the page-bar count chip shows the current connection name).

- **Overall layout and state** (data-view.js): left column with connection row + database row (docs/43 M3: the instance's catalog, primary first, system last, not-browsable disabled with the server's reason) + keyspace tree for redis (docs/43 M2) + lazy table list; right column with the OBJECT TAB STRIP (docs/42: every open table/key/console/activity is a tab, capped at eight, overflow into a list menu, dirty tabs marked and never silently dropped), then per-tab header (title/meta + segment + ONE primary action + overflow, docs/43 M4), filter bar, grid, STATUS line (pager, page size, editability in the server's words, connection name - separate from the commit bar), buffered bar. View-state factory `dbFreshState()` (conns/conn/tables/data/filters/updates/deletes/inserts/sel/sql*/tab/redis*, data-view.js:26-51); switching connections does a full reset (grep, sorting, buffers all cleared together; the comment at line 269 spells out why). Connection-type awareness `dbSyncKind()`: redis swaps the placeholder/hides Explain; connection label `name · dialect[ · read-only]` (306-308).
- **Browsing**: the table list pages server-side at 200/page (grep debounced 300ms); the sort row is a key select plus a direction toggle (↑/↓ with aria-labels) — SQL connections offer name/rows/size and append sort/dir to the request so the database does the ordering server-side, redis offers key/TTL and sorts client-side over the keys SCAN has already handed over (TTL puts expiring keys first, names via localeCompare — never raw byte order); switching connections or kinds resets the sort to name/asc (data-view.js:32,133,165,197-204,239-262,340). Table items show type/approximate row count/size; clicking opens a table (resets paging/sorting/filters/buffers, dbOpenTable). A redis connection swaps the same slot for a key list: continued SCAN ("More" appends the already-scanned keys), the filter box feeds the SCAN MATCH pattern (data-browsers.js:16-33).
- **Row grid** (data-grid.js): column headers carry type/PK marker/comment caption, and hovering shows the full column-comment card; clicking a header cycles three-state sorting (asc→desc→none, executed server-side); pager (prev page/next page, page size 10-500); row checkboxes (Shift range-select) for copying; NULL rendered explicitly.
- **Filter bar** (data-filters.js): a three-part column×operator×value form; operators map one-to-one onto the backend whitelist, values are plain text (bound as parameters server-side); for redis it becomes a pattern input + "N shown · M in keyspace" counters.
- **Editing** (data-edit.js/data-cell.js): double-clicking a short value (≤80 characters, single-line) opens an in-place floating editor; long/multi-line values open a sheet dialog (supports NULL/boolean toggling/JSON formatting); all modifications go into the **client-side buffer** (updates/deletes/inserts), and the amber bar counts them with a "LOCAL ONLY" hint; the "SQL" button previews the exact statements Commit will run (a client-side mirror of `buildEditStatements`, values inlined for display only); "Commit (1 transaction)" POSTs /edits after a second confirmation; "Discard" is a pure client-side drop, zero queries. + Row buffers a new row; the ✕ at the row head buffers a delete (undoable).
- **Querying** (data-sql.js): the SQL console has syntax-highlighted two-layer rendering and Ctrl+Enter to run; Run goes to /query (with the current page size as limit); Explain idempotently prefixes `EXPLAIN` client-side (mirroring the server's `with_explain`); history and favorites ride the console tab's toolbar overflow (docs/43 M4; the flat Run/Explain/Format row is gone), kept in localStorage (`swiss.dbSqlHistory`, at most 50 entries, only successfully run queries are stored); on a redis connection the same slot becomes the Command console, replies shown in a single-column grid.
- **Export/import** (data-csv.js/data-grid.js): the "CSV" button exports the current page/query result (pure client-side CSV+BOM assembly); "Export…" goes through /export to download an attachment (the confirm dialog states the 100k-row cap and reads the `X-Export-Rows` receipt); the "Import…" wizard: paste or upload a CSV → per-column mapping (match by name by default, skippable) → preview the first 3 rows → confirmed single-transaction submit; on failure the current state is preserved.
- **Copying**: right-click a cell to copy its value; whole rows copy as JSON/CSV/INSERT (dialect-aware quoting, buffered values win); checked rows bulk-copy as CSV/TSV/Markdown/JSON; the query-result grid works the same way.
- **Structure tabs and DDL** (data-structure.js): Columns/Indexes/Foreign Keys tables + a monospace DDL block (`dbAlignDdl` re-lays-out CREATE TABLE into an aligned layout); Table ▾ menu (the rename prompt validates `[A-Za-z0-9_$]{1,64}`, truncate/drop require typing the table name verbatim).

## Redis Stream Browsing (docs/45)

The stream view is the one value type with a view of its own (data-stream.ts); everything else about it is the /stream routes above.

- **XREVRANGE window, both directions**: the newest window is `XREVRANGE key + -`, older pages `(<before> -`, catch-up `+ (<after)` — exclusive `(` bounds (Redis 6.2+), newest-first always, so the panel never sorts (stream_window_args, redis.rs:375-384). XREAD/XREADGROUP stay on the blocking blacklist (docs/22: one shared connection must never be held) — following is polling, one pipeline of exactly three commands per tick (XREVRANGE + XLEN + XINFO STREAM), a budget pinned by a commandstats test.
- **The 500-row ring buffer**: the DOM never holds more than STREAM_ROW_CAP=500 rows; which end falls out depends on the direction — a walk of older pages drops from the top (the user reads the bottom), the live edge drops from the bottom (streamCap/streamMerge, pure and vitest-pinned; data-stream.ts:59-69,79+).
- **Follow**: one timer for the whole panel, interval 1/2/5 s, only while the tab is active and the document visible (a hidden tab skips the fetch, not just the paint); a view at the top rides the live edge, a view scrolled into history holds still and pools new entries behind an "↑ N new" pill whose click flushes and returns to the top; an error stops Follow and resets the toggle honestly; `more` on a live-edge page sets a sticky gap flag whose only honest exit is the jump.
- **The jump race guard**: `dbStreamJumpLatest` reopens the latest window on the gap bar's click — and issues its token on the SAME `dbFollowReq` guard the Follow ticks use, voiding any tick still in flight (its answer would pool a page behind a pill whose splice target the jump is about to replace); the converse is accepted, a tick issued after the jump supersedes it, and dedup-plus-sort makes a late live-edge page a no-op at worst (data-stream.ts:368-391).
- **Consumer groups are read-only**: the groups fold shows `name/consumers/pending/lag/last-delivered-id` from XINFO GROUPS, refreshed every 5th Follow tick; there is deliberately no XACK/XCLAIM/XTRIM/XDEL UI — those change someone else's consumption progress and belong behind a confirmation, not in a browser (docs/45 D4).

## Configuration and Storage

- **The Data plugin itself is zero-config and zero-disk**: `config_schema` is an empty object, `restart_on_config_change: false` (src/builtin.rs:428-453); enabling/disabling the plugin writes no files.
- **Connection definitions come from MCP** (Data only consumes): each browsable connection = one MCP registry entry, whose stable ID is the entry name (the gateway.config.json `mcps` key or managed.json). **Connection key contract** (called out in docs/09 §3 and docs/12 W3): a key must carry configuration identity, credential context, and read-only semantics — it cannot merge on host/port alone; the implementation is "the id is the registry entry name, and the entry already encodes the full definition": two definitions sharing host/port but differing in credentials are two entries, two names, never merged (catalog.rs:27-40 comment + the test `two_definitions_sharing_host_and_port_stay_two_connections` catalog.rs:533-553); `readonly` travels as a `ConnectionInfo` field and is branded into the pool session (MySQL `SET SESSION TRANSACTION READ ONLY`, PG `default_transaction_read_only=on`), so one connection can never be both read-only and writable.
- **Picker order owns no storage of its own**: the /api/db picker's ranking re-reads the sidebar's state live per request through the `OrderSource` closure — the flat manual order (`managed.json` `order`, written by the family's PUT /api/groups/mcps/order since docs/20 G2; duplicates collapse to their first slot, an empty list restores name order) sliced by group memberships (`groups` plus per-MCP assignments via PUT /api/groups, unassigned names rendering in the first group like `ManagedStore::group_of`) (app.rs:493-509,546-580;managed.rs:425-442,444-503).
- **Credential discipline**: ${ENV_VAR} and `secret://` references expand only at adapter build time (make_adapter, crates/swiss-mcp/src/adapters/mod.rs:284-298); the browser `label` contains only the target (`db @ host:port`/host:port db N), never a password (dbbrowser.rs:441-442;mysql.rs:600-613;pg.rs:687-697;redis.rs:874-884).
- **Client-side local state**: SQL history in localStorage (key `swiss.dbSqlHistory`, cap 50, data-view.ts); all other view state lives in memory and is released on unmount.

## Lifecycle and Background Behavior

- **Data has no background tasks and no eager resources**: `DataInstance::start` is a no-op (comment: starting without a catalog provider is legal too; routes answer an honest 503, inventory shows the dependency unmet); `stop` is equally empty — request-scoped leases die with their requests, and dropping the /api/db boundary releases them (builtin.rs:400-417). The 6-second panel poll never rebuilds this view (rendering contract, data-view.js header comment).
- **Lease lifecycle** (catalog.rs): request enters handler → `lease_db`/`lease_redis` first runs `catalog_guard` (presence resolves Serving/Stopping/Absent), then `catalog.lease(name, "data")`; provider-side `RegistryCatalog::lease` looks up the registry, `LeaseTracker::grant` counts +1 and mints a `ConnectionLease` (carrying BrowserFlavor); the handler holds the lease until the browser calls complete, and Drop counts -1 and wakes the drainer — **there is no "remember to return it" API left to forget** (catalog.rs:154-197).
- **Provider stop choreography** (MCP plugin stop, src/builtin.rs:176-189, in docs/12 W3 order): `begin_withdraw` (no new leases issued, the seat is kept) → `drain_leases` (`DRAIN_TIMEOUT_MS`=5 s; info log while waiting, on timeout a warn log naming the unreleased count "closing with unreleased connection leases") → `registry.close_all()` (actually closes pools/kills child processes) → `catalog.clear()` (releases the seat, remembers last_provider_id so the 503 can name names).
- **Enable/disable without leaks**: after 100 register/withdraw/clear cycles the registry returns exactly to zero (catalog.rs:478-503); a provider stopping while leases are held is not yanked away — the 5-second window covers one bounded /api/db page or one console round trip, and only on timeout does it "close with unreleased leases" and warn honestly (catalog.rs:128-153).
- **Run logs**: `data view import` (info), `data view ddl` (**warn** — destructive operation), `data view commit` (info), `data view redis commit` (info, with the command count), `data view activity kill` (**warn** — the one route that interrupts someone else's work), all carrying name/table or pid/counts (dbbrowser_api.rs).

## Relationship to the Host and Other Plugins

- **The connection catalog = the only seam where the two plugins cooperate** (docs/12 W3, replacing the old `browser_resolver` closure): `CatalogRegistry` is a typed capability seat in `RuntimeServices`, constructed at the composition root and **outliving any plugin instance** (a provider that stops and starts again finds the same seat, swiss-host/src/services/mod.rs:49-56). Only one provider may be registered at a time; duplicate registration errors and names the incumbent — silent overwrite is not allowed (catalog.rs:244-260); during withdraw the seat still belongs to the drain (catalog.rs:428-437).
- **MCP = provider, Data = consumer**: at the end of the MCP plugin's start (deliberately last, so a failed start leaves no fake catalog) it registers `RegistryCatalog` (the registry itself implements ConnectionCatalog: one row per registry entry, including non-browsable "none" rows so the 404 can name the type) together with one `LeaseTracker` per instance into the catalog (builtin.rs:158-174;registry.rs:826-933).
- **The same connection serves both MCP tools and Data browsing**: browsers and MCP tools share the **same** `Arc<Lazy<Pool>>` — the MysqlEngine comment says outright that one pool serves tools, resources, ping, and the panel's Data view (mysql.rs:544-546); the `browser()` hook mints MysqlBrowser/PgBrowser/RedisDataBrowser on demand but only clones the Lazy pool's Arc, never building a second pool (mysql.rs:748-753;pg.rs:857-865;redis.rs:1030-1040;adapters/mod.rs:272-274). The pool's first open is lazy (Lazy); real connections are established on demand.
- **Who opens, who closes**: only the Data side takes leases (the holder is always `"data"`, dbbrowser_api.rs:202,224); MCP tool calls do not go through leases (the pool is theirs to begin with). **Open**: every /api/db request; **close**: Drop at request end (the waiter is the provider's drain); the **real closer of the pool** is MCP's `close_all()`, and only after withdraw+drain — "disable MCP" does not yank the rug out from under a page being served, and disabling Data only reclaims its own request-scoped leases, with no collateral damage in the other direction (docs/12 W3 test list).
- **Honest dependency declaration**: the Data descriptor `requires: ["connection-catalog"]` (a capability name, not a plugin id); the composition root installs the capability probe, and inventory's `requiresMet` reflects in real time whether MCP is providing (builtin.rs:381-385;server.rs:238-249;engine.rs:480-485). With MCP disabled, every /api/db route answers a uniform 503 that names it, rather than an empty list pretending "you have no databases" (dbbrowser_api.rs:166-190).
- **A second host-supplied seam — the picker's order source**: `OrderSource` arrives exactly the way the catalog does (an `Extension` injected by the composition root), but the closure's body reads the host's managed store and MCP registry (src/app.rs:493-509); swiss-data still depends on neither — the ranking inputs are composed in `build_app`, so "plugin crates do not depend on each other" holds while the picker honors host-owned sidebar state (the same order GET /api/mcps ranks by).
- **Host boundary**: the routes are mounted inside the host's loopback guard/body limit/plugin boundary; when the plugin is disabled the host answers 503 (app.rs:600-618). Workspace dependency edge: swiss-data depends only on swiss-core/swiss-host (crates/swiss-data/Cargo.toml) and has **zero dependency** on swiss-mcp — only after W3 does "plugin crates do not depend on each other" actually hold (docs/12 W5).

## Style and Design Observations

**Project-wide patterns followed/demonstrated**:

1. **Plugin descriptor registration**: one factory + one `host.register` line; pages/routes/dependencies are all data (builtin.rs:66-86,369-391); the host has zero match arms — Data (a plugin built out of someone else's connections) proves "add a capability without touching the core" in reverse.
2. **Route mounting**: `dbbrowser_router<S>` is generic over state, the catalog goes through the Extension layer, and after merging into build_app it automatically sits inside the loopback guard/body limit/plugin boundary — the same pattern as the Tunnels/Jobs routes.
3. **Error handling**: the `{error}` Node shape, driver messages passed through verbatim (most useful to a grid user), 404 texts preserved verbatim, 503 naming the missing party; nowhere in the crate does `unwrap()` touch a database/network path.
4. **Naming and porting discipline**: module names (dbbrowser-api.ts → dbbrowser_api.rs), constant names, error strings, and JS coercion semantics (`js_number`/`js_to_string`, hand-written replicas of `Number()`/`String()`) all align with the Node build; the panel JS is the spec for the admin API (an AGENTS.md principle).
5. **Memory discipline**: Data has zero eager resources and zero background tasks; paging is always server-side (LIMIT/OFFSET+COUNT); export caps at 100k rows in 5k chunks; Redis pipelines batch 200 at a time; browser objects are minted on demand and the shared pool is never copied; disable means real release (request-scoped leases).
6. **Honesty principle** (docs/09 §4): what disable actually does is spelled out item by item in the `DataInstance` comment; "no provider" answers a naming 503 rather than an empty list; `requires/requiresMet` makes cross-plugin dependency visible data; a drain timeout warns honestly that it is "closing with N unreleased leases".
7. **Typed capability-seat pattern**: catalog and shell (services/mod.rs:16-18) share one shape — single provider, lease, withdraw→drain→close; and like the ActionRegistry family, "duplicate registration is a visible conflict".
8. **Sorts refuse rather than default; order is read live**: `browse_table_sort` rejects unknown keys/directions for the same reason `browse_order` does — a silently dropped sort changes what the pages show — and both adapters turn the verdict into a single ORDER BY string swap inside the paged statement instead of re-sorting in memory; the picker's ranking is a closure over host state evaluated per request (never a snapshot captured at mount), and its rank-first comparator (rank first, name between equals — never both) mirrors Node's /api/mcps comparator guard.

**Inconsistencies/exceptions (found in this audit)**:

- **Task wording vs code**: the task says `/api/data/*`, the code prefix is `/api/db` (a Node-era name); only the plugin id is called data. Cite /api/db when referencing this document.
- **Stale comment (the code has moved ahead)**: the pg_browser.rs module header (lines 2-5) still calls buffered edits/CSV import-export/DDL "answer not available in this build", but the same file fully implements apply_edits/export_table/import_table/ddl_op (lines 338-531) — a mid-port leftover comment that contradicts the implementation.
- **`with_explain` exists twice**: the server keeps dbbrowser.rs:1242 with tests anchoring that contract, but the Explain prefix is actually added by the panel client (data-sql.js:143-146 is the mirror implementation); today only tests reference the server-side version.
- **Stale panel comment**: the data-view.js header comment claims page size "default 500", while the code says `pageSize: 50` (line 36) and the server says `BROWSE_DEFAULT_PAGE`=50 (dbbrowser.rs:96) — the backend wins (the panel cannot be modified in this repo).
- **redis's `editable` is computed at the route layer** (`dialect != "redis"`, dbbrowser_api.rs:58) rather than self-reported by the browser — because the RedisBrowser trait has no dialect(); a small-seam decision, an understandable exception.
- **The console's read-only era is gone**: the docs/22 parity batch made the console single-statement-but-writable — `assert_single_statement` is now the one rule (mysql_browser.rs:361-363;pg_browser.rs:370-372, both comments: "reads and writes alike go through — this console belongs to the panel on the operator's own machine"), `is_read_only_sql` no longer exists in sql.rs, and the readonly connection flag guards only the structured edit paths.
- **`with_explain` allows EXPLAIN ANALYZE** (it executes a SELECT, read-only) but rejects EXPLAIN INSERT — read-only semantics are adjudicated uniformly at the statement-shape layer, not the prefix layer (dbbrowser.rs:1236-1241), the finest gate in the implementation.
