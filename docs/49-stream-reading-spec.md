# 49 — 快速流怎么读：过滤、分组概览、阅读时暂停

> 状态：**已实施**（2026-09-29）。基线 master `cf47007`。docs/45 把 Redis Stream 变成了"看得见、撑不爆"的
> 表格；本文解决它留下的下一个问题——**看得见不等于读得懂**。
>
> 需求原文（owner，2026-09-29，在远端 redis 跑了 9 个 symbol × 10 条/秒的行情压测之后）：
> 「很好，现在应该看出问题了，这么高速的信息，我怎么过滤？怎么查看相关信息？毕竟很快就刷过去了？你有什么
> 比较好的方法吗？」
>
> 压测实测（远端 2 核 2G，`market:fast`，无 MAXLEN，90 条/秒）：服务端几乎无感——4.5 分钟写入 24,210 条，
> 键占 3.3 MB（约 137 B/条），redis `used_memory` 3.91M → 6.21M，`/var/lib/redis` 768K → 1.3M，
> load 0.00。撑不住的是人眼和面板，见 §0。

## 0. 现状与缺口

docs/45 的 stream 视图在 90 条/秒下的三个硬伤，都不是 bug，是**缺功能**：

- **表格 6 秒换一遍。** `crates/swiss-panel/panel/src/data-stream.ts:71` 的 `STREAM_ROW_CAP = 500`，
  Follow 每秒灌进 90 行 ⇒ 不到 6 秒整屏全换。想读某一行，只能关掉 Follow，而关掉就不知道这期间发生了什么。
- **一秒档已经贴着服务端窗口上限。** `crates/swiss-host/src/dbbrowser.rs` 的
  `STREAM_WINDOW_DEFAULT = 100`：90 条/秒时 1 秒档刚好够，**2 秒/5 秒档必然触发 gap 条**（中间被跳过）。
  也就是说，慢一点看反而看得更少。
- **没有任何过滤或分组。** 视图里只有 Follow 开关、间隔、pending 药丸、gap 条、速率读数、消费组折叠
  （`data-stream.ts` 的 `dbStreamFollowBar`）。想只看 NVDA，没有任何手段；redis 本身也不会帮忙——
  流的字段没有索引，`XREVRANGE` 只能按 id 范围取。

## 1. 决定

| # | 决定 | 理由 |
| --- | --- | --- |
| D1 | 过滤在**服务端**做，不是只过滤面板已持有的 500 行 | 只过滤本地 = 只能在最近 6 秒里找 NVDA。历史翻不回去，等于没做 |
| D2 | 服务端过滤是**有界回扫**，并且**如实报告扫了多远** | redis 没有字段索引，扫是唯一诚实的做法。既然要扫，预算和进度就必须摆在明面上，不能让 0 条命中看起来像"流里没有" |
| D3 | 过滤语法用 shlex 切分，三种词形（`=` 精确、`~` 包含、裸词全文），多词 AND | 快速流的读者在做的事就是"减少"。AND 就是减少；OR 等于什么都不减。切分不手写——house rule，redis 控制台刚为此付过一次代价（`swiss-ui-privacy-and-libraries`） |
| D4 | 分组概览**自动选字段**，不等用户去开 | 90 行/秒没人能读，9 个数字可以。默认不开 = 没人会发现它 |
| D5 | 鼠标停在表格上 = 暂停在活动边缘，移开自动恢复 | "读的时候别动"不该是一个需要先想起来去按的开关。这与已有的"滚动到历史时暂停"是同一条规则，只是换了个触发方式 |
| D6 | 不做 OR、不做取反（`-symbol=NVDA`）、不做正则 | 三种词形覆盖了压测里所有真实问句。取反和正则是下一轮的事，等有人真的要 |

## 2. 设计

### 2.1 过滤语法（`swiss-host/src/dbbrowser.rs:848` `StreamTerm` / `:916` `parse_stream_filter`）

一行过滤条件切成若干**词**，每个词一种匹配，**全部命中**才留下：

| 写法 | 含义 | 例 |
| --- | --- | --- |
| `字段=值` | 该字段精确等于（忽略大小写） | `symbol=NVDA` |
| `字段~值` | 该字段包含 | `data~error` |
| 裸词 | id、时间戳、任一字段值里出现即可 | `600519.SH` |

- 切分交给 **shlex**（`swiss-host/Cargo.toml`，与 redis 控制台同一份依赖）：`data~'"last": 12'` 是
  **一个**带空格的词；引号不闭合直接报错，而不是从中间劈开。
- 大小写只在**值**上忽略：字段名是流自己选的线上数据，不是要人反复输入的文案。
- `=` 或 `~` 出现在**第 0 位**（`=42`）不算分隔符——那是有人在输值，按空字段名去匹配会永远静默地命中 0 条。
- 行内没有词（空串、全空白）= 没有过滤，面板就是这样清空它的。

### 2.2 有界回扫（`swiss-mcp/src/adapters/redis.rs:590` `read_stream_window`）

无过滤时一切照旧：`XREVRANGE + XLEN + XINFO` 一个 pipeline，**每 tick 恰好三条命令**（docs/45 的预算，
由 `follow_polling_costs_three_commands_per_tick` 钉死）。

有过滤时改成走一遍：

```
每页 XREVRANGE 500 条（STREAM_SCAN_PAGE），从 bound 的高端往下，bound 自己的低端保持不变
  → 解码 → 留下命中的
  → 攒够 count 条 / 扫满 20,000 条（STREAM_SCAN_BUDGET）/ range 见底，就停
```

- **bound 的低端不能动**：Follow tick 的 `after=游标` 如果换成单纯的 `before=上页最后一条`，回扫就会越过
  游标，把看过的再看一遍。`stream_range_ends`（`redis.rs:399`）把两端拆开，只让高端往下走。
- 答案多带三个字段（只在过滤时出现，**缺席 ≠ 0**）：
  - `scanned`：这次检查了多少条；
  - `scannedFrom`：检查到的**最新** id —— Follow 的下一个游标。这条最关键：如果拿"最新命中的一条"当游标，
    一个一分钟才命中一次的过滤，每 tick 都会把这一分钟里的 5,400 条重读一遍；
  - `scannedTo`：检查到的**最旧** id —— Load earlier 的续点。同理：否则"两万条里命中 3 条"之后再点一次
    Load earlier，扫的还是同一批两万条。
- `more` 的含义随之精确化：**不是**"这页满了"，而是"**不是因为 range 见底才停的**"——攒够了 count 或
  扫满了预算，都意味着更老的地方可能还有命中。Follow tick 上 `more=true` 依旧点亮 gap 条，因为那确实是
  一段被跳过的区间。
- 预算取 20,000 条 ≈ 3 MB 流数据，环回地址上几百毫秒；页大小 500 与面板行上限同数量级。

### 2.3 分组概览（`data-stream.ts:141` `streamSummary` / `:179` `streamAutoField`）

表格上方一行**芯片**，每个是被分组字段的一个值：`NVDA 56 · 9.9/s`。点一下 = 把过滤设成 `字段=值`
（值含空格或引号时按 §2.1 的规则加引号）。

- 纯函数，**只读面板已持有的行**，不发请求——概览是对屏幕上这段窗口的一次归纳。
- 速率的分母是整段持有窗口的**时间跨度**（最新 id 的毫秒 − 最旧 id 的毫秒），所有值共用一个分母，
  因此各值速率相加等于流的速率。跨度为 0（只有一行、或同毫秒）时不显示速率：除以 0 得到的是 ∞，∞ 不是读数。
- **自动选字段**：按列序找第一个"像维度"的列——去重后 2 ≤ 值数 ≤ 24，且值数 × 2 ≤ 有值行数。
  行情里 `symbol` 有 9 个值，`price`/`seq` 一行一个值，后者分组会画出 500 个芯片。行数 < 4 时不猜。
- 用户从下拉里选了字段就以用户的为准，选"不分组"（空串）也是一个会被记住的决定。
- **自动选定后就不再换**（19998 走查发现）：过滤成 `symbol=NVDA` 后，symbol 只剩一个值、不再"像维度"，
  概览条于是跳到了 `price`——用户刚把问题问窄，回答却换成了另一个问题。只要那一列还在，就继续用它。
- **芯片数量有上限**（12），剩下的只报个数：9 个芯片已经换行，二十多个会把它本要概括的表格顶出屏幕。
  芯片本就按量排序，所以被截掉的那一截正是最不值得画的。

### 2.4 阅读时暂停（`data-stream.ts:278`）

鼠标进入表格 ⇒ `redisStreamHold = true`；下一个 tick 照常 fetch，但把新页**压进已有的 pending 池**
（docs/45 §2.3 的那个池和那个药丸），表格一行不动。移开鼠标，下一个 tick 自动把池并回活动边缘。

- 与"滚动到历史时暂停"完全同一条路径：`pinned = isTopPinned(...) && !hold`。没有新机制，只多了一个触发。
- Follow 开着且处于 hold 时，栏里写一句"阅读中已暂停——移开即恢复"。否则表格不动会被读成卡死，
  而卡死是活动视图最不能有的样子。

### 2.5 面板其余接线

- **输入框跨重绘保留**：过滤在最后一次敲键 400 ms 后生效，而生效就是一次整窗重绘；重建的 input 是新节点，
  焦点、光标与输入法状态都没了，下一个键会打在空处。所以正在输入的那个节点被原样传给新的 bar（移动节点仍会
  失焦，因此重绘后显式回填焦点与光标）——docs/31 的 MCP 日志搜索框付过同一笔学费。

- 每个窗口请求都带上过滤（`dbStreamUrl`）；消费组折叠不带——那是关于流的，不是关于"读哪几条"的。
- 换过滤 = **换一个窗口**（`data-stream.ts:703` `dbStreamApplyFilter`）：旧行是对旧问题的回答，
  拼在一起会呈现出一张从未存在过的表。输入框 400 ms 防抖，回车立即生效（与键名模式框同一套做法）。
- 过滤后命中 0 条时，空状态换成"已扫描的条目中没有符合此过滤的"，**输入框保留**——唯一能撤销这片空白的
  控件不能跟着空白一起消失。
- hits 读数（"最近扫描 20000 条，命中 1 条"）在 Load earlier 时**累加**，因为那是同一次回溯的继续。

## 4. 没做的（明确留白）

- **OR / 取反 / 正则**（D6）。
- **按时间或 id 跳转**：现在只能 Load earlier 一页页回溯。高速流里"回到 00:38:54"是个真实需求，下一轮。
- **超速时的显式抽样**：速率超过窗口能力时，现在靠 gap 条事后报告，而不是事先声明"90/s，每秒展示最新 100 条"。
- **服务端聚合**：分组概览只归纳面板持有的窗口。要"过去一小时每个 symbol 多少条"得由服务端扫，代价与
  §2.2 同级，但目前没人要。
